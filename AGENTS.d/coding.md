# 编码规范 / 设计原则 / 熔断机制

## 1. 语言编码规范

- Go 代码必须遵守 `docs/standards/go-编码规范.md`；
- 其他语言引入前，先补对应规范到 `docs/standards/`。

## 2. 设计原则

- **文件即真源**：记忆文件是 canonical state，SQLite 索引是 derived state（eventually consistent），可随时 `--rebuild-index`；
- **资源意识**：低资源服务器（2 核 / 1.8GB），常驻内存 <60MB、空闲 CPU≈0、事件驱动禁轮询；
- **极简依赖**：能用标准库不引第三方；新增依赖必须写进设计文档并经用户批准；
- **原子写**：临时文件 → rename → 索引；禁止出现半态。

## 3. 熔断机制

编码中遇以下情况立即熔断并向协调者报告，不得无限重试：

- 同一问题连续失败 ≥3 次；
- 实现与已批准设计偏离；
- 资源预算突破（内存/CPU 超红线）；
- 发现设计缺陷导致任务书不可行。

熔断报告必须包含：现象、已尝试方案、建议决策（改方案/降级/终止）。
