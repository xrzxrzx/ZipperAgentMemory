# 记忆仓库读写规则（docs/memory/）

## 1. 定位

`docs/memory/` 是项目**跨会话、跨 Agent 的记忆仓库**——恢复上下文与事实的唯一权威来源。
**任何重要决策、状态变更、阶段结论必须在此留痕**，然后才谈得上「记忆」。

## 2. 结构

| 文件 | 用途 |
|------|------|
| `README.md` | 仓库说明与索引 |
| `status.md` | 当前状态快照：阶段、决策表、调研、待办、红线 |
| `decisions/YYYY-MM-DD-主题.md` | 决策记录（ADR 风格：背景/决策/理由/后果） |
| `research-交叉验证笔记.md` | 协调者抽查记录（如调研验证） |

## 3. 读写规则

- **开工前**：新会话/新 Agent 先读 `status.md` 与最新决策；
- **变更后**：重要变更立即更新 `status.md`，保持「当前事实」；
- **决策时**：新决策写入 `decisions/`，并更新 status.md 决策表；
- status.md 不保留历史（历史见 git）；禁止在 status.md 里堆积过时信息。

## 4. 质量要求

- 简洁、可验证、可执行；
- 引用具体文件路径，不靠模糊描述；
- 状态与 `docs/design.md`、代码保持同步（同步一致原则）。
