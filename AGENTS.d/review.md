# 代码审查

## 1. 触发

- 阶段交付前，对代码做一次审查；
- 用户要求 review 时。

## 2. 方式

并行两个审查子 Agent，双轴对照：

1. **规范轴**：代码是否符合 `docs/standards/go-编码规范.md`（命名/错误处理/并发/路径沙箱/原子写/资源红线）；
2. **规格轴**：代码是否符合任务书与 `docs/design.md`（功能/接口/验收标准）。

## 3. 审查报告要求

- 按严重度分级：阻塞（必须修）/ 建议（可修可不修）/ 信息；
- 每条注明：位置、问题、依据（规范/规格条款）；
- 阻塞项修复后复审通过才可提交。

## 4. 原则

- 审查不代写代码，只指出问题与方向；
- 修复由原编码 Agent 完成，或由协调者决定重派。
