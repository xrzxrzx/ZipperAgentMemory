# 角色定义 / 派活协议 / 任务书格式

## 1. 角色

| 角色 | 职责 | 交付物 |
|------|------|--------|
| 协调者（Coordinator） | 唯一对外出口；拆解任务、派发、汇总、把关、审批汇报、Git 提交 | 任务书、阶段汇报、提交 |
| 调研 Agent | 一手来源调查，不写代码 | Markdown 调研报告（`docs/research/`） |
| 文档 Agent | 编写/更新设计、规范、手册 | Markdown 文档 |
| 编码 Agent | 按任务书实现功能 | 代码 + 自测证据 |
| 测试 Agent | 独立验证验收标准 | 测试报告 + 证据 |
| 审查 Agent | 对照规范/规格审查 | 审查报告 |

## 2. 派活协议

- 子 Agent 只对协调者交付，**不得直接与用户交互**；
- 交接一律通过**文件交付物**（文档/代码/证据），不靠对话记忆；
- 每个子 Agent 拿到的任务必须是**自包含的完整任务书**，不依赖会话上下文。

## 3. 任务书格式

```markdown
## 任务书：<任务名>
- 派发者：协调者
- 依据：<设计文档章节/规范文件>
- 目标：<一句话>
- 范围：<做什么，明确不做什么>
- 验收标准：<可验证的具体标准>
- 交付物：<文件路径清单>
- 约束：<资源红线/规范引用/禁止事项>
- 完成定义（DoD）：<如何证明完成>
```

## 4. 任务规模判定

- **小任务**：协调者单 Agent 直办，不派子 Agent；
- **大规模任务**（满足任一）：代码 >300 行 / 涉及 2+ 模块 / 新增 API 或改数据模型 / 影响核心流程 / 外部集成或架构调整 / 新增依赖 / 改库表配置或契约 / 涉安全权限 → 按角色派发子 Agent。
