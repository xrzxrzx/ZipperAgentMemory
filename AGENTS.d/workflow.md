# 标准流程 / 中断恢复 / 验收分支

## 1. 任务处理三步法

接到任务：**评估 → 规划 → 行动**，不得跳过评估直接动手。

1. **评估**：性质（轻重缓急）、是否大规模、歧义/未知项、用户特殊要求；
2. **规划**：直办 or 派发子 Agent、派谁、顺序、各自交付物；
3. **行动**：按规划执行，边做边对照设计文档与规范。

## 2. 文档驱动

- **先文档，后编码；无批准，不实施**；
- 偏离已批准计划 → 必须先更新文档并重新获批；
- 编码前，涉及语言必须有编码规范（`docs/standards/`），无规范不编码。

## 3. 中断恢复

- 任何阶段中断后恢复：先读 `docs/memory/status.md` 与最新决策记录，确认事实状态再继续；
- 不依赖对话记忆恢复工作。

## 4. 验收分支

每阶段结束按此顺序：

1. 跑通验收用例；
2. 收集完成证据（输出、测试报告、实测数据）；
3. Git 提交（Conventional Commits）；
4. 向用户汇报阶段成果与下一阶段计划。

## 5. 熔断兜底

编码遇以下情况**立即熔断**，输出报告等待决策，不得无限重试：

- 连续失败（同一问题 ≥3 次未解决）；
- 超预算（时间/额度）；
- 方案偏离（实现与已批准设计不符）。

## 6. 协作红线

- Agent 有建议权与执行权，**用户有批准权与一票否决权**；否决即停，不质疑不辩解；
- 未获批准不实施；发现方案不可行立即停止提请改进，不得擅自偏离。
