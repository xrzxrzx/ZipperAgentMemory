## 2. 技术目标与约束

| 目标 | 约束 |
|---|---|
| 只读浏览 + 检索 + 下载全库 | 常驻内存红线 **<60MB**（现 22.1MB）；禁止引入向量库/embedding |
| 入口 `https://zipper.net.cn/memory/` | 复用现有证书（不新签、不新建子域） |
| token 长期有效，服务器侧可查 | **token 不进仓库、不进日志、不进命令行参数（`ps` 可见）、不进会话记录** |
| 不破坏现有能力 | `/mcp` 路由与 IP 白名单策略不变；索引为 derived state，可随时重建 |

## 3. 方案选型

| 决策 | 选定 | 备选与否决理由 |
|---|---|---|
| 进程形态 | **同进程双监听**：8931（MCP，不变）+ 8932（Web，仅 127.0.0.1） | 独立 Web 进程需第二份 store/index 与内存占用，触碰内存红线 |
| 认证载体 | **持久 Cookie + Bearer 双通道**：`POST /memory/api/login` 校验 token 后下发持久 cookie（HttpOnly/Secure/SameSite=Lax，10 年）；同时接受 `Authorization: Bearer` 供 curl/脚本 | 纯 Bearer 不可行：**浏览器顶层导航不发送 Authorization 头**，刷新即掉登录。URL 携带 token 会把口令写进访问日志与浏览历史，否 |
| token 存储 | **独立文件**（默认 `<workdir>/web-token`，权限 600，内容一行） | 放 config.json 里不便查看（需解析 JSON）；独立文件用 `cat` 即可读，且生命周期与配置解耦 |
| token 生成/轮换 | 新增子命令 `web-token -config <path> [-init [-force]]`：原子写、自动 0600、**只打印长度不打印值** | 手改 JSON 易错；`sed` 对 base64 特殊字符不安全 |
| Markdown 渲染 | **服务端 goldmark**（新增依赖，MIT，纯 Go，**默认不渲染原始 HTML**：替换为 `<!-- raw HTML omitted -->`） | 客户端 marked + innerHTML 会执行库内**外部抓取资料**里的脚本；DOMPurify 需再 vendor 一个库且安全依赖配置正确 |
| 目录树 | 按层惰性加载（`tree?path=`） | 一次遍历全库拖慢首屏 |
| 防爆破 | 同 IP 失败 10 次/分钟 → 429（内存计数 + 周期清理） | token 是全库唯一防线，必须有闸 |
| 静态资源 | `go:embed` 进二进制（无 CDN 依赖） | 外链 CDN 在断网/墙内不可用，且引入第三方请求 |

### 3.1 架构

```
浏览器 ──https://zipper.net.cn/memory/──► nginx :443（复用现有证书）
                                            ├─ location /memory/ → 127.0.0.1:8932
                                            └─ location /        → 404（主域首页继续下线）

同一进程 zipper-agent-memoryd
  ├─ :8931  /mcp              MCP（IP 白名单，契约不变）
  └─ :8932  /memory/*         只读 Web UI（token 认证）──► memory.Store + index.Index
```

### 3.2 需求 REQ-01 验收标准的细化（原「无 token → 401」）

因浏览器导航无法携带 `Authorization` 头（见 §3 认证载体），判定标准细化为：

| 请求 | 期望 |
|---|---|
| `/memory/api/*` 无凭据或错 token | **401**（JSON，不含任何库内容） |
| `/memory/` 页面导航无凭据 | **302 → `/memory/login`** |
| 正确 token（Bearer 或 Cookie） | **200** |
| 同 IP 失败 ≥10 次/分钟 | **429** |

## 5. 数据与接口设计

### 5.1 配置文件（`config.json`）

```json
{
  "allow_ips": ["127.0.0.1", "120.228.125.194"],
  "autocommit": { "enabled": true, "hour": 0 },
  "web": {
    "enabled": true,
    "addr": "127.0.0.1:8932",
    "token_file": "/opt/zipper-agent-memory/web-token"
  }
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `web.enabled` | `false` | 关闭时不监听、不读 token 文件（与旧版行为一致） |
| `web.addr` | `127.0.0.1:8932` | `-web-addr` 显式给出时优先（flag > 配置 > 默认） |
| `web.token_file` | `<config 同目录>/web-token` | 必须存在且权限不含 group/other 读写位，否则启动失败 |

**token 规则**：base64url 编码的 32 字节随机值（**43 字符**，RawURLEncoding 无 padding）；**只能来自文件**，不接受 flag；日志只打印 token 长度与文件路径，不回显口令本身。

### 5.2 HTTP 接口（全部挂在 `/memory/`）

| 方法 | 路径 | 认证 | 说明 |
|---|---|---|---|
| GET | `/memory/login` | 公开 | 口令输入页（纯静态，无库内容） |
| POST | `/memory/api/login` | 公开（受限流） | 体 `{"token":"…"}`；成功 → `Set-Cookie: zam_token=…; Max-Age=315360000; HttpOnly; Secure; SameSite=Lax` |
| POST | `/memory/api/logout` | 需要 | 清 cookie |
| GET | `/memory/api/status` | 需要 | `{files, bytes, last_modified}` |
| GET | `/memory/api/tree?path=` | 需要 | 目录项（目录在前，按名排序，不递归） |
| GET | `/memory/api/file?path=` | 需要 | `{path, size, mtime, kind:"markdown"\|"text"\|"binary", html\|text}` |
| GET | `/memory/api/raw?path=` | 需要 | 原始字节 + `Content-Disposition: attachment`（文件名 RFC 5987 编码） |
| GET | `/memory/api/search?q=&mode=and\|or&limit=` | 需要 | `{mode, hits:[{path, snippet}]}`；`limit` 默认 20、上限 100 |

- 所有 `path` 经 `memory.Store` 的路径沙箱校验（`pkg/memory/memory_store.go:60-83`），穿越返回 400/403；
- 单文件展示上限 1MB，超过只允许下载；
- 所有响应 `Content-Type: …; charset=utf-8`；HTML 响应带 `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`；
- 认证响应不回显任何库内容；错误一律 `{"error":"…"}` 不含路径细节。

### 5.3 搜索语义（`pkg/index`）

```
输入：`隧道 端口`      → tokenizeForFTS → "隧 道" / "端 口" 两个词元
AND 模式：`"隧 道" AND "端 口"`      → 两词都出现的文件（默认）
OR  模式：`"隧 道" OR "端 口"`       → 任一词出现的文件
```
词元内部仍走 CJK 单字短语（保证中文子串匹配）；所有词元加引号 + 内部引号加倍，用户输入不会造成 FTS5 语法错误。

### 5.4 nginx（`/etc/nginx/conf.d/zipper-net-memory.conf`）

```nginx
server {
    listen 80;
    server_name zipper.net.cn www.zipper.net.cn;
    location /memory/ { return 301 https://$host$request_uri; }
    location / { return 404; }
}
server {
    listen 443 ssl http2;
    server_name zipper.net.cn www.zipper.net.cn;
    ssl_certificate     /etc/nginx/ssl/zipper.net.cn/zipper.net.cn.pem;
    ssl_certificate_key /etc/nginx/ssl/zipper.net.cn/zipper.net.cn.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_session_cache shared:SSL_zipper:10m;
    location /memory/ {
        proxy_pass http://127.0.0.1:8932;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        client_max_body_size 1m;
    }
    location / { return 404; }
}
```

> 现有的 `zipper-net-ssl.conf.disabled` / `zipper-net-http-redirect.conf.disabled` **保持禁用不动**（它们会开放主域首页，与 REQ-08 冲突）。

## 8. 风险与回滚

| # | 风险 | 缓解 | 回滚 |
|---|---|---|---|
| R1 | token 泄露 = 全库（含密码资料）泄露（**用户已知情接受**） | 仅 HTTPS；HttpOnly+Secure cookie；32B 随机；日志脱敏；失败限流 | 轮换：`web-token -init -force` + `systemctl restart zipper-agent-memory` |
| R2 | Web 代码崩溃连累 MCP（同进程） | handler 全包 panic recover；Web 与 MCP 路由隔离 | 换回备份二进制 + restart |
| R3 | nginx 改动影响其他站点 | 只**新增** conf，不修改现有；改后先 `nginx -t` | `rm` 新 conf + `nginx -t` + `systemctl reload nginx` |
| R4 | 443 安全组未放行导致外部不可达 | 部署前与用户确认；不可达则记录为待办，不影响内网可用 | 无需回滚（仅入口不通） |
| R5 | 搜索语义变更影响既有调用 | 已在 §6 显式声明；单词查询行为不变 | 回到 `Search()` 默认 AND；如需旧短语语义，`SearchMode` 可扩展 `ModePhrase` |
| R6 | 新增依赖引入风险 | goldmark 纯 Go、无 CGO、只用于渲染 | 去掉依赖，降级为纯文本展示 |

**部署回滚清单**（逐条命令，见 `实施方案.md §1`）：二进制、config.json、nginx conf 三处各有备份与还原命令。
