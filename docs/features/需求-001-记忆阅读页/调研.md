> 依据：立项前摸底（用户 2026-10-05 提出「给 memory.zipper.net.cn 加阅读页 + 不过期 token」）　日期：2026-10-05　状态：已完成

## 1. 调研问题

1. `memory.zipper.net.cn` 现在是什么状态（DNS、证书、反向代理、端口）？
2. 现有记忆守护进程对外提供什么接口？有没有认证机制？
3. 记忆库里有什么内容？有没有敏感数据？
4. 用户报告的「多关键词搜索搜不到」是否成立？根因是什么？
5. 构建与部署路径是否可用（服务器 Go 工具链、本地交叉编译、依赖拉取）？

## 2. 结论摘要（先行给出）

1. **`memory.zipper.net.cn` 不存在**：DNS 返回 NXDOMAIN，且无泛解析；主域 `zipper.net.cn` A 记录 → `8.141.89.50` ✅
2. **主域 HTTPS 处于下线状态**：443 未监听，vhost 被改名为 `.disabled`；现有证书 SAN **仅**含 `zipper.net.cn` / `www.zipper.net.cn`（有效期至 2026-12-05）→ 子域需另签证书，故本次改用**路径式入口** `https://zipper.net.cn/memory/`
3. **守护进程只提供 MCP**（`/mcp`），访问控制仅 IP 白名单，**没有 token 概念、没有网页**
4. **多关键词搜索确认失效**：整串查询被包成**一个 FTS5 连续短语**，导致词越多越搜不到；实测「隧道 端口」0 命中，而单词「隧道」3 命中
5. **构建路径**：服务器 Go 工具链不可用（`go version` 超时），构建走**本地交叉编译**；`goproxy.cn` 可达（HTTP 200），可新增依赖

### 3.4 搜索行为实测（同一查询分别以单/多词执行）

```
# /opt/zipper-agent-memory/zipper-agent-memoryd search -root memory -limit 5 "<query>"
"隧道"        → 3 hit(s)      ✅
"端口"        → 5 hit(s)      ✅
"隧道 端口"   → 0 hit(s)      ❌
"记忆 索引"   → 1 hit(s)      （仅因正文中恰好存在连续四字「记忆索引」）
```

根因：`pkg/index/index.go:217`
`phrase := "\"" + strings.ReplaceAll(tokenizeForFTS(query), "\"", "\"\"") + "\""`
——整个查询（含空格）经 CJK 单字切分后包成**一个**短语，等于要求所有字**连续且有序**出现。

## 5. 候选方案对比

| 维度 | 方案 | 取舍 |
|---|---|---|
| 阅读入口 | A 新建 `memory.zipper.net.cn` 子域 | 需新签证书 + 新 DNS 记录 + 安全组，链路长；本次不选 |
| | **B 路径式 `https://zipper.net.cn/memory/`** | 复用现有证书与已解析主域，**已选**（用户 2026-10-05 决定） |
| | C 仅本机/SSH 隧道访问 | 最省事但达不到「浏览器随时可读」目标 |
| 认证载体 | 单一静态 token | **已选**（用户要求「不过期」） |
| | 短期会话 + 刷新 | 与「不过期」诉求冲突，否 |
| Markdown 渲染 | 服务端 goldmark（默认不渲染原始 HTML，替换为 `<!-- raw HTML omitted -->`） | **已选**：库内存在**外部抓取**的资料，客户端 innerHTML 直渲染会执行其中脚本 |
| | 客户端 marked + DOMPurify | 需 vendor 两个第三方 JS，安全性靠配置正确，否 |
| 进程形态 | 同进程双监听（8931 / 8932） | **已选**：内存红线 <60MB（现 22MB），无需第二份索引连接 |
| | 独立 Web 进程 | 多一份 store/index 与内存占用，否 |
