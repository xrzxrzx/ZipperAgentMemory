# 需求-002-子域测试页

> 状态：已确认　版本：v1　更新：2026-10-13

## 1. 背景与要解决的问题

记忆阅读页（需求-001）目前的入口是路径式 `https://zipper.net.cn/memory/`。用户希望有一个 **`memory.zipper.net.cn` 子域**上的页面，用来确认这个子域"到底能不能用"。

调研（见 §5）发现两件事使原始设想无法直接实现：

1. **该子域没有 DNS 记录**（`223.5.5.5` / `8.8.8.8` 均返回 NXDOMAIN）——DNS 解析发生在客户端，**nginx 无法代替 DNS**；
2. **现有证书不覆盖该子域**（SAN 仅 `zipper.net.cn` / `www.zipper.net.cn`），而用户明确选择**不签证书**。

## 2. 用户与场景

| 项 | 内容 |
|---|---|
| 使用者 | 用户本人 |
| 场景 | 在自己电脑的浏览器里打开 `memory.zipper.net.cn`，确认子域整条链路（解析 → nginx → 页面）是否可用 |
| 前提 | 客户端自行指定解析（hosts 文件）；不签证书；页面为纯静态测试页 |

## 3. 需求条目

| 编号 | 要什么 | 为什么 | 验收标准 | 优先级 |
|---|---|---|---|---|
| REQ2-01 | `http://memory.zipper.net.cn/` 打开能看到一个最简测试页 | 验证子域链路可用 | 在客户端指定解析后，浏览器打开该地址显示测试页（HTTP 200，页面含域名标识） | P0 |
| REQ2-02 | 无需 DNS 记录、无需证书即可验证 | 用户不想加 DNS、不签证书 | 仅凭客户端 hosts 一行 + 服务器 nginx vhost 即可访问；HTTP 下**无任何浏览器告警** | P0 |
| REQ2-03 | 该子域只提供静态文本，不代理任何后端 | 安全：明文 HTTP 上不能出现口令/Cookie 流量 | 该 vhost 不出现 `proxy_pass`；阅读页仍只走 `https://zipper.net.cn/memory/` | P0 |
| REQ2-04 | 页面之后可随时替换为正式入口 | 现在是测试，将来可能把阅读页搬过来 | 页面内容与 vhost 均为独立文件/独立 server 块，不影响其他站点；撤销只需删一个 conf | P1 |
| REQ2-05 | 其他站点与主域行为完全不变 | 生产环境，不能影响现有业务 | 变更前后现有 6 个 nginx 配置文件哈希一致；8081–8084、博客、阅读页状态码不变 | P0 |

## 4. 不做什么

- ❌ 不加 DNS 记录（由用户按需自行在控制台添加）
- ❌ 不签任何证书（用户明确"不签"）→ 因此 `https://` 会先报域名不匹配，属**预期**
- ❌ 不在该子域上代理记忆阅读页（避免明文 HTTP 传输口令与 Cookie）
- ❌ 不落盘任何静态 HTML 文件（页面由 nginx 内联返回，服务器零文件残留）

## 5. 待确认项

**无未决需求问题。**

已知外部依赖（非需求问题）：若希望**其他设备**（手机等）也能访问，需用户自行添加 DNS A 记录 `memory` → `8.141.89.50`；仅加 hosts 时**只有该台设备**可访问。

## 6. 术语表

| 术语 | 含义 |
|---|---|
| 子域 | `memory.zipper.net.cn`（相对主域 `zipper.net.cn`） |
| 客户端指定解析 | 在 hosts 文件里写死"域名 → IP"，绕过 DNS 查询 |
| 测试页 | 仅用于确认链路可用的最简页面，不含业务功能 |
