# 需求-003-子域分发框架

> 状态：已确认　版本：v1　更新：2026-10-13

## 1. 背景与要解决的问题

用户的构想：**所有子域都解析到同一台服务器**，再由 nginx 按 `server_name` 把各子域代理到不同端口上的服务（多服务统一入口）。

调研（2026-10-13 实测）发现三件事必须先处理：

1. `memory.zipper.net.cn` 此前**没有 DNS 记录**（NXDOMAIN）——已由用户添加**通配 A 记录**（`*` → `8.141.89.50`）解决；
2. 服务器 `:443` **没有默认 vhost**——通配解析一生效，任何"未配置的子域"都会掉进第一个 443 server 块（**博客**），表现为"随便什么域名都显示我的博客"；
3. 用户选择**不签证书** → 子域一律 HTTP；HTTPS 只能复用主域证书（浏览器会提示域名不匹配，属预期）。

## 2. 用户与场景

| 项 | 内容 |
|---|---|
| 使用者 | 用户本人（服务器上还跑着 4 个测试站点与博客） |
| 场景 | ① 以后新增服务时，直接用 `<服务名>.zipper.net.cn` 指过来；② 乱敲/未配置的子域要有明确、不误导的落点 |
| 前提 | 通配 DNS 已生效；本阶段不签证书；需要鉴权的服务（阅读页）仍留在主域 HTTPS 路径下 |

## 3. 需求条目

| 编号 | 要什么 | 为什么 | 验收标准 | 优先级 |
|---|---|---|---|---|
| REQ3-01 | 任意一级子域都解析到本机 | 多服务统一入口的前提 | `dig`/解析任意 `*.zipper.net.cn` 均得 `8.141.89.50`；主域 `@` 记录不受影响 | P0 |
| REQ3-02 | 未配置的子域有**明确落点**，不落到其他站点 | 否则"乱敲的域名"会显示博客，误导且难看 | 未配置子域返回 **404** 且页面写明「此子域尚未配置」；**不得**出现博客/阅读页内容 | P0 |
| REQ3-03 | 已配置的名称**优先级不受影响** | 生产环境不能因兜底而抢走既有站点 | `zipper.net.cn`「www」「memory.zipper.net.cn」的响应与变更前完全一致 | P0 |
| REQ3-04 | 兜底块不代理任何后端 | 明文 HTTP 上不得出现需鉴权的流量 | 兜底 vhost 内无 `proxy_pass`；阅读页仍只在 HTTPS 主域路径 | P0 |
| REQ3-05 | 子域↔后端的映射有**单一真源** | 以后加服务不靠记性 | 映射表落文档；新增服务 = 一个 server 块 + （如需 HTTPS）一条签证书命令 | P1 |
| REQ3-06 | 其他站点与主域**零影响** | 同机还跑着 4 个测试站点与博客 | 变更前后现有 nginx 配置文件哈希逐一致 | P0 |

## 4. 不做什么

- ❌ **不签证书**（用户决策）→ 子域 HTTPS 会提示域名不匹配，属**已知预期**，不是缺陷
- ❌ **不把阅读页搬到子域**（用户决策；无证书时明文跑口令不可接受）
- ❌ 不做 DNS 以外的解析改造（内网 DNS / hosts 分发不在本需求范围）
- ❌ 不引入自动化配置生成（当前只有一个测试页，手写 server 块足够；服务数量上来再议）

## 6. 术语表

| 术语 | 含义 |
|---|---|
| 通配解析 | DNS 记录 `*`，使任意一级子域都指向同一 IP（不含主域本身，也不含多级子域） |
| 兜底块 | `server_name *.zipper.net.cn` 的 vhost，承接未单独配置的子域 |
| 映射表 | 子域 → 用途 → 后端的对应关系（见 `验收.md §5`） |
