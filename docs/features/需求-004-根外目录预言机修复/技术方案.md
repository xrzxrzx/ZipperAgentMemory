> 状态：S2 待批准

## 1. 方案概述

把 `pkg/web` 中两处裸 `os.Stat` 换成 `memory.Store` 新增的**沙箱内元数据查询**（`IsDir` / `ModTime`），
使「一切文件系统访问必经 `memory.Store` 路径沙箱」成为结构性事实；越界路径在 `resolve` 处即失败，预言机随之消失。

```
修复前：Read(rel) ─越界失败─▶ pathIsDir(rel) ── os.Stat(Join(root, rel)) ──▶ 根外被 Stat ──▶ 文案可区分（泄露）
修复后：Read(rel) ─越界失败─▶ Store.IsDir(rel) ─ resolve(rel) ─越界即 ErrPathOutsideRoot ─▶ 永不触及文件系统 ─▶ invalid path
```

## 3. 接口与数据

新增 API（`pkg/memory`，导出 + 文档注释，符合规范 §2 命名）：

```go
// IsDir 报告 rel 是否为根内目录。rel 经 resolve 沙箱校验：
// 越界返回 ErrPathOutsideRoot，解析/Stat 失败返回包装后的底层错误。
func (s *Store) IsDir(rel string) (bool, error)

// ModTime 返回 rel 的修改时间。rel 经同一沙箱校验（错误语义同 IsDir）。
func (s *Store) ModTime(rel string) (time.Time, error)
```

- **不新增数据、不改持久化结构、不改索引**（SQLite schema 不动，无需 `rebuild-index`）；
- **对外 HTTP 契约**：状态码语义完全不变（401/400/404 与鉴权、Cookie、限流一致）；唯一变化是越界路径响应文案统一为 `400 {"error":"invalid path"}`；
- **不新增依赖**：仅标准库 `os`、`time`（`pkg/memory` 已在用）。

**为什么不用另两种形态**：

| 备选 | 否决理由 |
|---|---|
| `Stat(rel) (os.FileInfo, error)` | 把文件系统类型暴露进包 API，与 `List` 返回自有类型 `Entry` 的既有风格不一致（JEV 0.14） |
| 让 `Read` 兼报哨兵 `ErrIsDirectory` | 改动 `Store.Read` 的对外错误契约，连带影响 `zam read` 与 MCP `memory_read` 的错误输出 → 超出本需求范围（JEV 0.01） |

## 6. 风险与回滚

| 风险 | 评估 | 处置 |
|---|---|---|
| 越界路径文案变化（`path is a directory` → `invalid path`） | 唯一对外可观察变化，属**收紧**；状态码不变。`design.md` §11.4 只规定状态码，未记载该文案（已核对） | 写入验收说明 |
| 根内符号链接指向根内 | `resolve` 成功 → `Stat` 跟随链接，行为与旧实现一致 | 单测覆盖 |
| 根内符号链接/junction 指向根外 | 旧实现会 Stat 跟随（可能返回 true）；新实现 `resolve` 直接判越界 → `invalid path` | 属预期收紧，单测覆盖 |
| 性能 | 每请求多一次 `resolve`（组件级 Lstat，深度上限 255）；阅读页为极低 QPS 场景 | 不引入缓存；`Status()` 的 WalkDir 量级远大于此 |
| 资源红线（规范 §10） | 无新增常驻内存、无 goroutine、无新依赖 | 红线不受影响 |
| 回滚 | 改动集中在 2 个生产文件；无数据迁移、无索引变更 | `git revert <short-hash>` 即可，无需重建索引 |
