## 1. 结论摘要

1. 报告所述「根外目录存在性预言机」**真实存在**，且已在本机用源码构建的实例**活体复现**（§2）。
2. 根因：`pkg/web` 在生产代码里**绕过 `memory.Store` 路径沙箱直接访问文件系统**——
   `handlers.go` 的 `pathIsDir` 与 `mtimeOf` 均用 `filepath.Join(root, rel)` + `os.Stat`，
   而拼接元字符串会先 `Clean`，越界路径因此被真正 Stat 到根外。
3. 报告未指出的两点：① 引入该代码的提交**自称**「在沙箱校验之后判定，避免探测口」，意图与实现相反；
   ② 现有回归测试只断言状态码 400，而两条分支**同为 400**，属结构性漏测（§3）。
4. 同类模式全仓排查后**仅此一处可被触发**（§4）。

## 2. 受影响代码路径（事实 + 行号）

| 位置 | 事实 |
|---|---|
| `pkg/web/handlers.go:167-187` | `handleFile`：`store.Read(rel)` 失败后进入 `if s.pathIsDir(rel)`（`:179`），命中则 400 `"path is a directory (use the tree API)"` |
| `pkg/web/handlers.go:226-244` | `handleRaw`：同构代码，`:238` 同样调用 `pathIsDir` |
| `pkg/web/handlers.go:276-282` | `pathIsDir` 定义：`os.Stat(filepath.Join(s.store.Root(), filepath.FromSlash(rel)))`，**未经 `resolve` 沙箱** |
| `pkg/memory/memory_store.go:60-83` | 沙箱 `resolve`：拒绝绝对/带卷名路径 → `Clean` 后判根内 → 组件级 `Lstat+Readlink` 判符号链接/junction 逃逸；越界返回 `ErrPathOutsideRoot` |
| `pkg/memory/memory_store.go:161-172` | `Read`：**先** `resolve`，越界即刻返回 `ErrPathOutsideRoot`——即 `pathIsDir` 执行时，越界事实**已经知道**，却被忽略 |
| `pkg/web/handlers.go:342-354` | `storeError`：`ErrPathOutsideRoot` → 400 `"invalid path"`；`os.ErrNotExist` → 404；其余 500 |

时序：`Read` 越界失败 → `pathIsDir` 仍 Stat 根外目标 → 目录返回可区分文案 → 预言机成立。

## 3. 活体复现（本地实例，只读探测；**未触达线上**）

复现方式：源码构建 `zipper-agent-memoryd serve`，临时 root `D:\temp\zam-repro\root`，
web 监听 `127.0.0.1:18932`（**刻意避开线上/常驻实例的 8931/8932**），口令取自临时 token 文件。

| 请求（Bearer 有效口令） | 目标真实状态 | 实测响应 |
|---|---|---|
| `/memory/api/file?path=../L1dir` | 根外·**存在的目录** | `400 {"error":"path is a directory (use the tree API)"}` |
| `/memory/api/file?path=../nosuchdir` | 根外·不存在 | `400 {"error":"invalid path"}` |
| `/memory/api/file?path=../sibling-file.txt` | 根外·**存在的文件** | `400 {"error":"invalid path"}` |
| `/memory/api/raw?path=../L1dir` | 根外·存在的目录 | `400 {"error":"path is a directory (use the tree API)"}` |
| `/memory/api/raw?path=../nosuchdir` | 根外·不存在 | `400 {"error":"invalid path"}` |
| `/memory/api/tree?path=../L1dir` | 根外·存在的目录 | `400 {"error":"invalid path"}`（tree 无裸 Stat，**无预言机**） |
| `/memory/api/file?path=../../../` | `D:\`（深层逃逸） | `400 {"error":"path is a directory (use the tree API)"}` |
| `/memory/api/file?path=L0dir` | 根内目录 | `400 {"error":"path is a directory (use the tree API)"}`（**合法行为，需保持**） |
| `/memory/api/file?path=nosuch.md` | 根内不存在 | `404 {"error":"not found"}`（**合法行为，需保持**） |
| 以上任一端点**不带凭据** | — | `401 {"error":"unauthorized"}` |

可判定推论：

- 泄露面 = **仅「根外某路径是否为已存在目录」1 bit/请求**；根外**文件**与根外**不存在**响应相同 → 无文件存在性、无内容泄露（与报告结论一致）；
- 逃逸深度不限（`..` 可任意叠加）；
- `/api/file` 与 `/api/raw` 均无速率限制（限流只在 `/api/login`，10 次/窗口/来源 IP），可自动化枚举；
- 前置条件：**必须持有效口令**（Bearer 或 `zam_token` Cookie）。

## 4. 文档与实现冲突（均为 T2 证据）

| 文档 | 原文位置 | 冲突 |
|---|---|---|
| 需求-001 验收 | `docs/features/需求-001-记忆阅读页/验收.md:258` | 记录该修复为「`pathIsDir`（**在沙箱校验之后**判定，避免"根外是否存在"探测口）」——与实现相反，**记录失实** |
| 设计文档 | `docs/design.md:280` | 「所有 `path` 经 `memory.Store` 路径沙箱校验（§6.2 同一实现），穿越一律拒绝」——`pkg/web` 两处 `os.Stat` 未走沙箱，与该声明不符 |
| 编码规范 | `docs/standards/go-编码规范.md:45` | 「所有用户/agent 提供的路径必须经沙箱校验」——同上 |
| 提交历史 | `53ac71e`（fix(web): 修复独立验证发现的 P2 缺陷） | 提交正文自称 `pathIsDir` 是「在沙箱校验之后判定」；同一提交亦为 `validateRelPath` 写下「**不做文件系统访问**……避免在越界路径上产生"根外是否存在"的探测口」的注释——防守意图明确，落点错误 |

补充事实：`docs/design.md:276` 的响应规范里「路径穿越 → 400」「目录路径 → 400」**状态码本身合规**，
缺陷在于两者**文案可区分**——修复方向是文案统一（收紧），不是改状态码。
