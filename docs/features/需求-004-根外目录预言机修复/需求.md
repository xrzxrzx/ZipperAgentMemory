# 需求-004 需求（S1）

> 状态：S1 待批准
> 前置：`调研.md`（S0，关键事实均为 T2 证据）
> 定级：**T2**（命中「安全权限」+「跨模块」两条；按「不确定时向上定级」执行）→ 三道批准门 S1/S2/S3

## 1. 目标

1. **堵住信息泄露**：消除 `/memory/api/file`、`/memory/api/raw` 上的「根外目录存在性预言机」——
   对越界路径，无论根外目标是否存在、是否为目录，响应必须**完全一致**。
2. **固化不变量**：把「**一切文件系统访问必须经 `memory.Store` 路径沙箱**」从口头约定变成结构性事实——
   阅读页（`pkg/web`）生产代码中不再出现直接文件系统调用；元数据查询（目录判定、mtime）同样走沙箱。
3. **文档与实现重新对齐**：修正失实的验收记录与误导性注释；编码规范补充该不变量的明确条款。

## 3. 范围

**在范围内**：`pkg/memory`（提供沙箱内的元数据查询）、`pkg/web`（改调用点、删除裸 Stat）、
两侧测试、`docs/`（本需求文档 + 上述文档更正）。

**明确不做**：

1. 不改任何 HTTP 状态码语义，不新增/删除端点，不改响应结构（唯一变化是越界路径文案**收紧统一**）；
2. 不动鉴权、Cookie、限流（含 `/api/login` 的 429 行为）；
3. 不动 `resolve` 三层沙箱语义本身（绝对路径 / 符号链接 / junction 判定一律保持）；
4. 不引入第三方依赖，不改 `go.mod`；
5. **不部署、不重启、不推送、不触达线上**（nginx 配置类加固属 `zipper-ops`，另开需求）；
6. 不做「顺手重构」：`mtimeOf`/`indexFile` 的调用点**行为保持不变**（仅并入沙箱口径），不改其成功路径语义；
7. 不处理报告中其它方向（鉴权变体、URL 规范化、反代信任头、XSS、CORS）——本轮只处理 Finding #63。
