## 1. 总体思路

分两批交付，**批 A 不改索引内容（零重建）**，**批 B 必须重建索引**：

| 批次 | 内容 | 是否重建索引 | 原因 |
|---|---|---|---|
| **A** | 别名扩展、排序加权、返回分数、片段 24→48 | **否** | 只改查询构造与 SQL 投影，索引内容与列结构均不变 |
| **B** | 中文二字组（精确率） | **是** | 新增 FTS 列 `body_bg` 并改变入库内容 |

批 A 可独立验收、独立提交；批 B 在其之上叠加。**批 B 不得与批 A 混在同一次提交**。

## 3. 接口与数据

### 3.1 别名表 `memory/meta/synonyms.tsv`

格式（UTF-8，无 BOM）：

```
# 注释行，以 # 开头
# 正词<TAB>别名1<TAB>别名2...
密码	password	pwd	口令
服务器	server	servers	主机
```

规则：

- 制表符分隔；首列为正词，其余为别名；**同组内对称扩展**（搜任一成员都能命中同组全部成员）；
- 空行、`#` 起始行忽略；列数 < 2 的行视为坏行**跳过**（不报错、不 panic，满足 AC2）；
- 单组上限 10 个成员，超出部分截断并在 `serve` 日志告警一次（防查询表达式爆炸）。

**加载策略**：`Index` 增加 `synMu sync.Mutex` + `synCache struct{ mtime time.Time; size int64; table map[string][]string }`。每次 `SearchMode` 先 `os.Stat`，`(mtime,size)` 未变则用缓存，变了重读。满足「改文件后无需重建索引即生效」（`需求.md` §4）。加载失败（文件不存在）→ 空表，**不报错**。

### 3.2 索引 schema（批次 B）

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS docs_fts USING fts5(
	tags, created, source, body, body_bg,
	path UNINDEXED
);
```

列序变为 `tags=0, created=1, source=2, body=3, body_bg=4, path=5`。

- **`body` 列内容不变**（单字切分，`tokenizeForFTS` 原样）→ `snippet(docs_fts, 3, ...)` 的列下标 3 **仍然正确**，不改；
- `body_bg` 存相邻二字组（`tokenizeBigramForFTS`），供 ≥2 字 CJK 查询；
- **双写是 AC7 的前提**：单字查询走 `body` 列，行为不回归。

### 3.3 二字组切分 `tokenizeBigramForFTS`

```
输入 "生日快乐"  → "生日 日快 快乐 "   （每个二字组自身是一个 token）
输入 "生，日"    → "日快"? 否 —— 逗号处断开，不生成 "生日"
输入 "生 日"     → 不生成 "生日"（有空格，不相邻）
```

实现要点：按 rune 遍历，**仅当 `runes[i]` 与 `runes[i+1]` 都是 CJK 且原文下标相邻**时输出该二字组；输出时二字组内**不加空格**（`unicode61` 把连续 Han 字符合成一个 token），组间加空格。

### 3.4 查询构造（AC1/AC6/AC7 的核心）

词元 → 子条件列表，词元之间按 `Mode` 连接；**每个词元内部为 AND**。

| 词元形态 | 生成条件 | 列限定 |
|---|---|---|
| CJK 且长度 ≥ 2 | 逐相邻二字组：`"生日"`、`"日快"`… 以 AND 连接 | `body_bg` |
| CJK 且长度 = 1 | `"生"` | `body` |
| 非 CJK（英文/数字） | 原样作为词 | **不限列**（让 `path` / `tags` 里的英文也能命中） |
| 中英混（如 `生日party`） | 按 CJK / 非 CJK 段切开，各自按上述规则生成后再 AND | 各按段 |

**别名扩展**在词元级进行：词元命中别名表某组 → 该词元展开为「组内全部成员各自生成的子条件」的 **OR**，整体作为一个词元条件参与外层 AND/OR。

示例：

```
查询「生日」           → body_bg:"生日"
查询「隧道 端口」      → body_bg:"隧道" AND body_bg:"端口"
查询「password」（表中有「密码 password pwd」）
                       → (body_bg:"密码" OR body:"password" OR body:"pwd")
查询「生」             → body:"生"
```

> 关键：≥2 字 CJK **绝不回落单字短语**（否则「生，日」仍会被 `"生 日"` 命中，AC6 不成立）。这是 FTS5 位置编号不保留原文间距（`调研.md` L2）的直接对策。

### 3.5 结果结构与分数（AC4 细化）

`index.Result` 增加字段：

```go
type Result struct {
	Path    string  // 不变
	Snippet string  // 不变
	Score   float64 // 新增：越大越相关；仅可用于同一查询内的相对比较
}
```

SQL 投影：`..., -1.0 * bm25(docs_fts, w_tags, w_created, w_source, w_body, w_bg, w_path) AS score`，`ORDER BY score DESC`。

列权重初值（批 A 为 5 列版本，批 B 为 6 列版本）：

| 列 | 批 A | 批 B | 理由 |
|---|---|---|---|
| tags | 10.0 | 10.0 | 标签是人工声明的强信号 |
| created | 1.0 | 1.0 | 弱信号 |
| source | 1.0 | 1.0 | 弱信号 |
| body | 4.0 | 4.0 | 正文 |
| body_bg | — | 6.0 | 精确二字命中，权重高于单字正文 |
| path | 8.0 | 8.0 | 文件名/路径即"标题"（AC3） |

> 权重为**初值**，S4 用 AC3 用例校准；改动权重只需改一行常量。

**三处出口的呈现**（AC4 判定细化——原表述"MCP 每项新增 score 字段"不准确，MCP 返回的是纯文本）：

| 出口 | 现状 | 本次 |
|---|---|---|
| MCP `memory_search` | `path: snippet` 文本（`tools.go:284-288`） | `path (score=3.21): snippet` |
| CLI `search` | `path: snippet`（`main.go:532-534`） | `path (score=3.21): snippet` |
| 阅读页 `/api/search` | JSON `searchHit{path,snippet}` | 加 `"score": 3.21`（**新增字段**，前端本轮不展示） |

### 3.6 索引版本保护（AC8）

- 约定 `indexSchemaVersion = 2`（批 B 起）；旧库 `PRAGMA user_version` 为 0；
- `Open` 读 `user_version`，不等于期望值 → 设 `ix.stale = true`（**不立即失败**，让 `serve` 能继续走 Rebuild）；
- `SearchMode` / `Upsert` 在 `stale` 时返回 `ErrIndexStale`（`errors.Is` 可判）；
- `Rebuild` 成功后执行 `PRAGMA user_version = 2`（字面量拼接，PRAGMA 不支持占位符）；
- `serve` 启动流程本就是「Open → Rebuild」，自动恢复；CLI / stdio 收到 `ErrIndexStale` 时**明确提示**「索引版本已过时，请执行 `rebuild-index`」。

> 选择「明确报错」而非「Open 内自动重建」：`Open` 拿不到 `memory.Store`（签名 `Open(dbPath string)`），强行改造会扩散改动面。

## 7. 风险与回滚

| 风险 | 影响 | 处置 |
|---|---|---|
| 索引体积 2.5–3×（双写：单字 2n + 二字组 3n 字符量） | 磁盘增长 | AC10 实测；超 3× 说明原因并按 §5.4 降级 |
| 二字组降低极短文本召回 | < 2 字的正文无 bigram | 单字列仍在，AC7 保证不回归 |
| 别名表被写出爆炸性表达式 | 查询变慢 / FTS 报错 | 单组 ≤10 成员 + 坏行跳过 + 词元数上限（沿用现有词元处理） |
| 旧索引与新代码不匹配 | 静默给出错结果 | AC8 版本检测 + `ErrIndexStale` 硬失败 |
| 改检索行为影响线上阅读页 | 生产体验变化 | **不部署**；部署属 `zipper-ops`，须单独批准 |
| 权重调不理想 | 排序不达预期 | 权重集中为常量，S4 用 AC3 用例校准即可，无需改结构 |

**回滚路径**：代码回滚到批 A/批 B 之前的提交 → 删除索引文件 → `rebuild-index`（索引是 derived state，无数据丢失风险）。记忆库文件（`memory/`）全程不被本需求修改。
