# 需求-005 需求（S1）

> 状态：S1 待批准
> 前置：`调研.md`（S0，关键事实均为 T2 证据）
> 定级：**T2**（命中「对外契约」+「数据模型」+「跨模块」三条；按「不确定时向上定级」执行）→ 三道批准门 S1/S2/S3

## 1. 目标

在不引入任何新依赖（**不引入向量 / embedding / 第三方库**）的前提下，把现有 FTS5 检索从「能搜到」提升到「搜得准、排得对、看得懂」：

1. **补上语义入口**：允许用英文词、口语词、别名命中中文正文（词表可自维护）。
2. **提高中文精确率**：消除「两个汉字被标点/空白隔开也算连续词」的误命中。
3. **让相关性可控**：路径/标签命中优先于正文顺带提及。
4. **让结果可解释**：检索结果返回相关性分数。
5. **让片段可读**：命中片段从 24 token 放宽到 48 token。

## 2. 验收标准（可判定）

| 编号 | 验收标准 | 判定方式 |
|---|---|---|
| AC1 | **别名扩展生效**：`memory/meta/synonyms.tsv`（UTF-8，每行「正词<TAB>别名…」，`#` 起注释行）中声明的别名可命中正词。例：表里有 `密码	password	pwd`，正文写「密码」的文件，搜 `password` **必须命中** | 新增用例：**改动前先跑一次留红档**（当前必然搜不到），改动后转绿；红/绿输出入 `验收.md` |
| AC2 | **别名向后兼容**：`synonyms.tsv` 不存在 / 为空 / 含坏行（列数不符、控制字符）时，检索行为与现状**完全一致**，且不 panic、不报 500；坏行被跳过不致命 | 表驱动单测：缺文件 / 空文件 / 坏行混合，断言既有查询结果集不变 |
| AC3 | **排序加权生效**：同一次查询中，关键词出现在**路径或标签**的文件，排序**优于**仅正文顺带提及的文件 | 构造两文件用例（一为 `notes/隧道配置.md`，一为正文顺带提「隧道」），断言路径命中者排名更前 |
| AC4 | **返回相关性分数**：MCP `memory_search` 每项新增 `score` 字段（数值，越大越相关）；CLI `search` 输出含分数。**现有字段 `path` / `snippet` 名称与语义不变** | 单测断言 JSON 含 `score`；CLI 端到端输出留档；阅读页 `/memory/api/search` 响应据此**新增**字段（向后兼容，前端不展示） |
| AC5 | **片段加长**：`snippet` 从 24 token 提升到 48 token | 用长正文（>200 字）断言命中片段字符数明显增加（对比改动前后） |
| AC6 | **中文精确率提升（二字组）**：≥2 字 CJK 词元的查询须按**原文相邻二字组**匹配，不得回落单字短语。判定案例：文件 A 含连续「生日」，文件 B 含被标点/空白隔开的「生，日」或「生 日」→ 搜「生日」**只命中 A** | **先红后绿**：改动前 B 会被误命中（因 FTS5 位置编号不保留原文间距，见 `调研.md` L2），红档留证；改动后 B 不命中、A 命中。⚠️ 该案例按 S0 推断成立，**S2 须先做红测确认**再据实修订本条 |
| AC7 | **单字查询不回归**：搜单个汉字（如「生」）仍能命中含该字的文件；英文/数字词元行为不变 | 现有用例 + 新增单字用例全绿 |
| AC8 | **索引版本保护**：索引引入内容版本标记；版本不符时必须**自动全量重建**或**明确报错并提示 rebuild**，**不得静默用旧索引出结果** | 手工把版本标记改旧 → 打开索引后断言已重建（或返回可识别错误）；两种行为择一，S2 定案 |
| AC9 | **回归与静态检查**：`go test -count=1 ./cmd/... ./pkg/...` 全绿；`gofmt -l .` 无输出；`go vet ./pkg/... ./cmd/...` 干净；`go build ./cmd/... ./pkg/...` 通过；**不新增任何依赖，不改 `go.mod`** | 命令输出留档（注意 `./...` 在本仓库基线即失败，见 `调研.md` C1） |
| AC10 | **资源红线不破**：服务 RSS 仍 **< 60MB**；索引体积增幅实测留档（预估约 2×，若 >3× 须在 `验收.md` 说明原因） | 本地 `serve` 实测 RSS + 索引文件体积对比 |
| AC11 | **文档同步**：`README.md` 检索说明更新（别名文件格式与位置、`score` 字段、二字组行为）；若需变更 `docs/design.md` 对切分方式的记载，**先停下重新获批**（`AGENTS.d/docs.md` §3），不得先改后报 | 文档 diff 核对 + 流程留痕 |

## 3. 范围

**在范围内**：

- `pkg/index/`：切分逻辑（`frontmatter.go`）、检索与结果结构（`index.go`）、索引版本标记（`index.go` / `rebuild.go`）、别名表加载与查询扩展
- `pkg/mcp/`：`memory_search` 返回结构新增 `score`
- `cmd/zipper-agent-memoryd/`：CLI `search` 输出分数
- 新增数据文件 `memory/meta/synonyms.tsv`（含示例与说明；随记忆库一起迁移）
- 两侧测试（`pkg/index/*_test.go`、`pkg/mcp/*_test.go`）
- 文档：`README.md`、`docs/features/需求-005-检索质量优化/*`、（如需）`docs/design.md` 走重新批准

**明确不做**：

1. **不引入向量 / embedding / Elasticsearch / 任何新第三方依赖**，不改 `go.mod`（`调研.md` §6 的评估结论）；
2. **不做「⑤ 敏感文件不入索引」**——用户 2026-10-18 明确选择不做，`password-vault.csv` / `servers.csv` 继续可被检索；该风险为**知情接受**（与决策 8 同性质），见 `调研.md` §5；
3. **不碰阅读页前端**（UI 美化、删除、回收站属 `需求-006`）；本轮仅保证 `/memory/api/search` 因结构体新增字段而附带 `score`，前端不改；
4. 不改 MCP 工具名与现有参数（`query` / `limit` / `mode` 不变），只**新增**返回字段；
5. 不改记忆库文件格式（Markdown / CSV 仍是真源），不引入新的存储引擎；
6. 不动鉴权、Cookie、限流；
7. 不改 `pkg/web` 生产代码逻辑（除编译必要处）；
8. **不部署、不推送、不重启线上服务**（生产部署属 `zipper-ops`，须单独批准）；
9. 不做画像 / 蒸馏 / 分层记忆（用户 2026-10-18 明确搁置）。

## 4. 边界与未知项

- **二字组的索引膨胀与内存影响**：预估正文 token 数约 2×（单字 n + 相邻二字组 n−1），需实测；若逼近内存红线，S2 需给降级方案（如仅对 ≥2 字词元建 bigram）。
- **`synonyms.tsv` 的生效时机**：每查询重读（简单、略慢）还是缓存 + fsnotify 失效（快、需处理并发）——S2 定案，S1 只要求「改文件后无需重建索引即可生效」。
- **别名扩展与 `mode` 语义的交互**：`ModeAND` 下多个词元的别名如何组合（每词元内部 OR、词元之间 AND）——S2 明确并写入测试。
- **线上历史索引**：生产服务启动即全量重建（`README.md:75`），故部署后自动对齐；本地旧索引由 AC8 的版本保护兜底。
- **Windows 编码**：`synonyms.tsv` 必须 UTF-8；PowerShell 5.1 环境下需显式 `-Encoding UTF8` 读取验证。
