## 4. 实施中的偏离与调整（诚实记录）

| # | 技术方案原设计 | 实际实现 | 原因 |
|---|---|---|---|
| 1 | 查询条件限定 `body_bg` 列 | **不限定列名** | `TestFrontMatterIndexed` 暴露：仅出现在 front-matter `tags` 里的中文（如「部署」）在限定列下查不到。改为不限列后，二字组 token 与单字 token 天然不混淆，AC6 的误命中不回归 |
| 2 | 方案未涉及元数据列切分 | 新增 `tokenizeMetaForFTS`（tags/created/source 单字 + 二字组**混写**） | 同上：让元数据里的中文可被 ≥2 字查询命中，同时保留单字匹配 |
| 3 | 索引体积预估 2.5–3× | 实测 **1.17×** | FTS5 倒排 + 前缀压缩使重复二字组几乎不额外占空间 |
| 4 | MCP 输出「新增 score 字段」 | 落地为文本 `路径 (score=x): 片段` | MCP 返回本就是纯文本（`tools.go:284-288`），无 JSON 契约可加字段；结构化 `score` 只在阅读页 JSON |

四项均为**实现细化**，不改变 AC 实质，已回写 `design.md §12`。
