## 1. 回收站存储结构

```
memory/
  .trash/
    20261018-203512/          ← 一次删除 = 一个批次目录（= 删除时间）
      notes/学习规划.md        ← 保留原相对路径，恢复即按此路径回填
    20261018-204001/
      projects/废弃方案.md
```

- **为什么按批次分目录**：删除时间天然可得（目录名），同名文件跨批次不冲突，恢复只需"批次目录下的相对路径"；
- `.trash` 是**点目录** ⇒ 索引自动跳过（`ShouldIndex`）、通用目录树自动不可见（§11.5）——不需要额外过滤逻辑；
- 空批次目录在恢复/清除后一并删除。

## 2. `pkg/memory` 新增能力（`trash.go`）

| API | 语义 |
|---|---|
| `MoveToTrash(rel string) (trashID string, err error)` | 移动到 `.trash/<新批次>/<rel>`；源不存在 → 错误；**不覆盖**已存在目标 |
| `ListTrash() ([]TrashEntry, error)` | 遍历批次，返回 `{ID, OrigPath, DeletedAt, Size}`，按删除时间倒序 |
| `RestoreFromTrash(id string) error` | 移回原路径；**原位置已存在 → 报错，不覆盖**（AC4） |
| `PurgeTrash(id string) error` | 物理删除该条目 |
| `ClearTrash() (int, error)` | 清空整个回收站，返回条目数 |

约束（沿用需求-004 的收口）：
- 一切路径先经 `Store.resolve` / 沙箱校验；
- `id` 形如 `<批次>/<原路径>`，解析后必须落在 `.trash` 内——**禁止 `..` 逃逸**；
- 不使用 `os.Rename` 跨卷兜底（同根目录下必然同卷），失败直接报错。

## 3. HTTP 接口（全部在 `/memory/` 前缀、全部需登录）

| 方法 | 路径 | 语义 | 备注 |
|---|---|---|---|
| `GET` | `/memory/api/trash` | 列出回收站 | 返回 `{count, entries[]{id, path, deleted_at, size}}` |
| `POST` | `/memory/api/delete` | 软删除 | body `{"path":"notes/a.md"}` |
| `POST` | `/memory/api/restore` | 恢复 | body `{"id":"20261018-203512/notes/a.md"}` |
| `POST` | `/memory/api/purge` | 清除单条 | body `{"id":"..."}` |
| `POST` | `/memory/api/trash/clear` | 清空 | 无 body |

**一致性**：删除/恢复/清除成功后同步维护索引（`Remove` / `Upsert`），使检索立即反映变化。

## 4. 安全设计（本需求的命门）

| 措施 | 说明 |
|---|---|
| **仅 POST** | 三个写接口对 GET 返回 `405`（AC6）。GET 有副作用的接口正是 CSRF 的经典入口 |
| **Cookie 保持 `SameSite=Lax`** | 跨站 POST 不携带 Cookie ⇒ CSRF 借不到凭据；**禁止**改为 `SameSite=None` |
| **Origin/Referer 同源校验** | 带该头且与请求 Host 不同源 → `403`；**缺失则放行**（非浏览器客户端不构成 CSRF 面，且测试/curl 可用） |
| **鉴权前置** | 写接口一律走 `protected`；未登录 `401` 且**不产生任何文件系统副作用**（AC7） |
| **沙箱** | 所有文件操作在 `pkg/memory` 内完成，`pkg/web` 不出现裸 `os.*` |
| **路径与 id 校验** | `path` 必须经 `resolve`；`id` 必须解析到 `.trash` 内，拒绝 `..` |

## 5. 前端（方案 A + 回收站子页）

- **视图切换**：`browse`（默认）/ `trash`。用 URL hash `#trash` 维持刷新后状态，浏览器后退可用；
- **侧栏底部只留一个小入口**：「回收站 3」——点击切到回收站视图；
- **回收站视图**：标题 + 条目数 + 「清空」+ 「← 返回」+ 表格（原路径 / 删除时间 / 大小 / 恢复 / 清除）；
- **文件栏新增「删除」按钮**（危险色），点击弹 `confirm` 后调 `/api/delete`，成功则从树里移除该节点并提示；
- 视觉沿用方案 A 的 token（`--accent #0969da`、圆角 8px、细阴影、hover 过渡）；
- **不引入框架、不引入构建**：仍为手写 CSS/JS。

## 6. 测试策略

| 层次 | 用例 |
|---|---|
| `pkg/memory` | 移动/列出/恢复/清除/清空；同名冲突不覆盖；`..` 逃逸拒绝；空批次目录清理；`.trash` 内路径解析 |
| `pkg/web` | 5 个接口的 200/400/401/403/405；GET 写接口 405；未登录无副作用；跨源 Origin 403；`.trash` 不经 `tree`/`file`/`raw` 可达 |
| 集成 | 删除 → 检索消失 → 恢复 → 检索回来；清除 → 物理不存在 |
| 前端 | 本地起服务手测：删除、回收站、恢复、清除、返回、刷新保持 |
