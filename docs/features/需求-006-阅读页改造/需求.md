# 需求-006 需求（S1）

> 状态：S1 待批准
> 前置：`调研.md`（S0）
> 定级：**T2**（「安全权限」+「对外契约」+「设计决策变更」）→ 三道批准门 S1/S2/S3

## 1. 目标

把阅读页从「只读浏览」扩展为「**可安全地软删除 + 回收站管理**」，并做一次视觉重构：

1. **软删除**：可把记忆库文件移入回收站（不物理删除），文件从正常视图与检索中消失。
2. **回收站区域**：单独查看已删除文件（原路径、删除时间、大小），不污染正常目录树。
3. **恢复**：从回收站还原到原位置；目标位置已被占用时明确报错、不覆盖。
4. **清除**：物理删除（单个 / 清空回收站），不可逆。
5. **界面重构**：按用户从 2 版视觉方案中选定的那版实现；同时容纳回收站入口与操作。
6. **安全模型更新**：`design.md` §11.1「不提供任何写接口」改为「仅提供**删除/恢复/清除**三类写接口，且受下述约束」。

## 2. 默认决定（用户未表态，按此执行；不同意请指出编号）

| # | 事项 | 默认 |
|---|---|---|
| D1 | 是否提供**恢复** | **提供**（软删除若无恢复即退化为延迟删除，价值不足） |
| D2 | 清除粒度 | **单个清除 + 清空回收站**，两者都做 |
| D3 | 回收站**自动过期** | **不做**（避免文件"悄悄消失"；由用户手动清空） |
| D4 | 回收站位置 | `.trash/`（点目录：天然不进索引、不进普通目录树） |
| D5 | 是否改 MCP 工具 | **不改**（删除能力只在阅读页；MCP 仍只有读写与检索） |

## 3. 验收标准（可判定）

| 编号 | 标准 | 判定方式 |
|---|---|---|
| AC1 | **软删除生效**：`POST /memory/api/delete` 成功后，文件从 `/api/tree` 消失、出现在回收站列表、检索结果中不再出现 | 端到端：写测试文件 → 删除 → 三处断言 |
| AC2 | **回收站可见**：`GET /memory/api/trash` 返回条目（原路径、删除时间、大小）；页面有独立回收站区域 | 接口单测 + 浏览器手测 |
| AC3 | **恢复生效**：`POST /memory/api/restore` 后文件回到原路径、重新可读、重新进检索 | 端到端 |
| AC4 | **恢复冲突不覆盖**：原位置已存在同名文件时恢复失败并给出明确错误，目标文件内容不变 | 用例：删除 A → 同路径新建 A' → 恢复 → 断言失败且 A' 内容未变 |
| AC5 | **清除**：单个清除与清空回收站均生效；清除后文件物理不存在、索引无残留 | 端到端 + 索引断言 |
| AC6 | **写接口仅 POST**：对三类写接口发 GET 一律 `405` | 表驱动用例 |
| AC7 | **鉴权**：未登录访问任一写接口返回 `401`，且**不产生任何文件系统副作用** | 用例：未登录调用后断言文件仍在 |
| AC8 | **跨站防护**：`Origin` / `Referer` 存在且与本站不同源时拒绝（403）；缺失时按既有策略处理并在文档中写明 | 用例：伪造跨站 Origin / Referer |
| AC9 | **沙箱不破**：路径穿越（`../`、绝对路径、符号链接逃逸）一律拒绝，且不在根外产生任何副作用 | 复用需求-004 的越界用例集 |
| AC10 | **只读能力不回归**：现有 `pkg/web` 测试全绿（该文件 37.7KB，是既有行为的主要防线） | `go test -count=1 ./pkg/web/` |
| AC11 | **回收站隔离**：`.trash/` 内容不出现在 `/api/tree`、不可通过 `/api/file`、`/api/raw` 或检索访问，只能经回收站专用接口 | 用例断言四个入口均不可达 |
| AC12 | **UI**：按选定方案实现，并通过截图比对（选定方案的静态原型 vs 实际页面）——主要内容区、侧栏、顶栏、状态栏、回收站区域一致 | 截图 + 人工确认 |
| AC13 | **回归**：`go test -count=1 ./cmd/... ./pkg/...` 全绿；`gofmt` / `go vet` / `go build` 干净；不新增依赖 | 命令输出 |
| AC14 | **文档同步**：`design.md` §11.1/§11.5 更新（写入能力与 `.trash` 隔离），台账/status 更新 | diff 核对 |

## 4. 明确不做

1. 不做多用户、权限分级、审计日志（单用户口令模型不变）；
2. 不改鉴权、Cookie、限流参数（`SameSite=Lax` **必须保持**）；
3. 不加 MCP 删除工具（D5）；
4. 不做回收站自动过期（D3）；
5. 不做"彻底隐藏 `.trash` 之外的其它点目录"策略变更——`.git` 等仍不可见；
6. 不做前端框架引入（仍是手写 HTML/CSS/JS，保持零构建）；
7. 不改记忆库文件格式；
8. 不做批量选择删除（本轮只做单文件删除 + 清空回收站）。

## 5. 边界与未知项

- **UI 验收方式**：以用户选定的静态原型为基准做截图比对；主观项不做"更好看"的模糊判定。
- **`.trash` 与点目录策略的张力**：需要在通用策略上开一个**精确例外**（只允许回收站专用接口访问 `.trash`），不得放宽为"允许所有点目录"。
- **`web_test.go` 改造**：现有用例断言"无写接口"的语义可能需要更新为新语义（仍须保证只读能力回归测试全绿）。
- **生产部署**：用户已明确授权「改完自己部署测试」；部署窗口内阅读页可能短暂重启。
