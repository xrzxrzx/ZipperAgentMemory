# 需求-007 视觉暗色改版（需求）

> 状态：已确认（用户 2026-10-20 指示「页面再优化一版，参照 Windows 的 Fluent Design，要暗色主题」）
> 前置：`需求-006-阅读页改造`（现行浅色「精致工具风」）
> 定级：**T1**（纯前端视觉，无接口/数据/权限变更）→ 需求随方案一起批，实施后截图验收

## 1. 背景与要解决的问题

阅读页当前是**浅色**「精致工具风」（`--accent #0969da`、白底卡片）。用户希望：

1. 视觉升级为 **Windows 11 Fluent Design** 的语言（材质、层级、圆角、动效观感）；
2. 采用**暗色主题**（长时间阅读不刺眼，与 Windows 暗色环境一致）。

## 2. 用户与场景

| 项 | 内容 |
|---|---|
| 使用者 | 用户本人（也会在手机窄屏上看） |
| 场景 | 夜间/长时间翻阅笔记与检索；桌面浏览器为主，手机浏览器为辅 |
| 前提 | 页面仍是零构建的手写 HTML/CSS/JS，静态资源 `go:embed` 进二进制 |

## 3. 需求条目

| 编号 | 要什么 | 为什么 | 验收标准 | 优先级 |
|---|---|---|---|---|
| REQ7-01 | 暗色 Fluent 视觉 | 用户明确要求 | 五个视图（首页/文件/CSV/回收站/登录）无浅色残留；Mica 底纹、8px 面板圆角、4px 控件圆角、层级阴影、`#60CDFF` 强调色、Segoe 字体栈 | P0 |
| REQ7-02 | **功能零回归** | 现有功能是命门（尤其回收站/软删除） | 登录 → 树展开 → 打开 md/csv/txt → 搜索 → 下载 → 删除 → 回收站 → 恢复 全链路行为与改版前一致 | P0 |
| REQ7-03 | 可访问性 | 暗色容易牺牲可读性 | 正文/次级/三级文字与强调色、危险色的对比度均 **≥ 4.5:1**（WCAG AA）；键盘 `Tab` 有可见焦点框；`prefers-reduced-motion` 时不播动效 | P0 |
| REQ7-04 | 零外部依赖 | 现有约束：无 CDN、无框架、无字体下载 | 页面不产生任何外部请求（除本站静态资源）；不新增依赖 | P0 |
| REQ7-05 | 登录页仍自包含 | 静态资源需鉴权，登录页若外链样式会被 401 拦 | 登录页样式内联、无 `/memory/static/*` 引用；既有用例 `TestLoginPageSelfContained` 保持绿 | P0 |
| REQ7-06 | 截图验收 | UI 主观项要有可复核基准 | 六张截图（桌面 1440×900 五个视图 + 窄屏 430×900）随验收文档提交 | P1 |
| REQ7-07 | **网站图标用用户头像**（2026-10-20 追加） | 用户要求；同时消掉既有的 `favicon.ico 404` | 标签页图标显示头像且**多分辨率**（16/24/32/48/64/128 的 ICO，避免小尺寸发糊）；iOS 有 180×180 触摸图标；**未登录的登录页也能显示**；控制台无 favicon 404；图标路由公开但只暴露图片本身 | P1 |

## 4. 不做什么

- ❌ **不做明暗切换开关**（用户选定「只要暗色」，避免多一套状态与测试面）
- ❌ 不改任何接口、数据格式、鉴权、Cookie、限流
- ❌ 不改 `app.js` 逻辑（回收站/路由/请求一行不动）
- ❌ 不引入前端框架 / 构建链 / 网络字体
- ❌ 不做移动端专门适配（沿用现有「窄屏堆叠」策略）

## 6. 术语表

| 术语 | 含义 |
|---|---|
| Fluent Design | Windows 11 的设计语言：材质（Mica/亚克力）、层级阴影、圆角、强调色、焦点框、克制动效 |
| Mica | Windows 11 的窗口底色材质：以壁纸色调做极淡晕染（Web 上用低透明度径向渐变近似） |
| 亚克力（Acrylic） | 半透明 + 背景模糊的材质（Web 上 `backdrop-filter`，不支持时回落纯色） |
| Fluent 焦点框 | 键盘焦点时在控件外画 2px 强调色描边（替代浏览器默认 outline） |
