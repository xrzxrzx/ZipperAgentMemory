## 1. 架构

```
[公网] 阿里云 8.141.89.50                         [内网] ZIPPER-WIN-SERV 192.168.7.104
  zipper-agent-memoryd (8931/8932)  ← 不变          zipper-resources.exe :8940
  memory/assets/index.md  ← 清单（进索引）             D:\ZipperResources\
        ↑ AI 检索命中                    ↓ AI 内网直取      ├─ avatars/
        └────────── 逻辑 ID ────────────────────────────→ ├─ wallpapers/{editor,lockscreen,common}/
                                                          └─ packages/
```

- **清单**：`memory/assets/index.md`（Markdown，进 FTS 索引，AI 可搜）；
- **字节**：104 的 `D:\ZipperResources\<category>/<file>`，**不在 `memory/` 树内** ⇒ 天然不进索引；
- **服务**：104 上新增 `zipper-resources`（只读 HTTP，仅内网）；
- **上传**：SCP 到分类目录 → 服务**自动发现**（不开放上传接口）；
- **公网**：只读清单，资源 URL 不可达（不做映射）。

## 2. 关键设计

| # | 决策 | 理由 |
|---|---|---|
| 1 | **不通过 MCP 传字节** | 工具结果只给 ID + 元数据 + URL；大文件走 HTTP |
| 2 | **服务只读** | 无上传接口 ⇒ 攻击面最小；上传靠 SCP 到磁盘 |
| 3 | **sha256 缓存** | 以 `(size, mtime)` 为键，未变则复用，避免每次全量重算 |
| 4 | **ID = 相对路径**（正斜杠） | 自解释、可直接拼 URL、无需额外映射表 |
| 5 | **服务监听 `0.0.0.0:8940` + Windows 防火墙限 `192.168.7.0/24`** | 与 Gitea(3000) 同款做法；公网不可达由网络层保证 |
| 6 | 目录分类固定五类 | `avatars` / `wallpapers/{editor,lockscreen,common}` / `packages` |

## 3. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | `{"ok":true}`，供部署探活 |
| GET | `/api/list` | 清单 JSON：`{root, count, updated, entries[]{id,name,size,sha256,mime,mtime}}` |
| GET | `/<id>` | 下载/查看单个资源（只读、防穿越、`Cache-Control: no-store` 不适用时按静态处理） |
