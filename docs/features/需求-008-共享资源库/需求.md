# 需求-008 共享资源库 需求（S1）

> 状态：S1 待批准
> 前置：`调研.md`（S0，含用户 2026-10-20 决策：**方案 A**）
> 定级：**T2**（新增对外契约 + 新增外部服务 + 跨机器部署）→ 三道批准门 S1/S2/S3

## 1. 目标

让 AI 能**发现并获取**记忆库之外的共享资源（头像、安装包等二进制文件），同时**不破坏现有公网体验、不引入大文件外网传输**。

1. **资源区独立**：二进制字节放内网服务器（104）的磁盘，**不进 `memory/` 目录树**——天然不污染检索与索引。
2. **清单桥接**：资源清单与元数据写进记忆库（Markdown，**进索引、可被 AI 检索**），每条含逻辑 ID + 大小 + sha256 + MIME + 用途 + 标签。
3. **内网获取**：资源经内网只读 HTTP 服务提供（`http://192.168.7.104:<port>/<ID>`），**不暴露公网**。
4. **AI 自动使用**：AI 检索清单 → 拿到 ID 与元数据 → 内网直取 → 用 sha256 自校验。
5. **公网诚实降级**：公网只能读到清单（知道"有这个资源"），资源下载**明确不可用**——不假装可用。

## 3. 验收标准（可判定）

| 编号 | 标准 | 判定方式 |
|---|---|---|
| AC1 | **清单可检索**：向资源区放入 `avatar/test.png` 并登记后，`memory_search "头像"` 命中清单条目 | 端到端（MCP 或 CLI search） |
| AC2 | **元数据完整**：清单条目含 `ID / 名称 / 大小 / sha256 / MIME / 用途 / 标签 / 登记时间` | 清单文本核对 |
| AC3 | **内网可取且校验通过**：从内网机器 `curl http://192.168.7.104:<port>/avatar/test.png` 得到的字节，sha256 与清单一致 | 实测 + `sha256sum` 比对 |
| AC4 | **公网不可下载**：从公网访问资源 URL 返回**连接失败/超时**（不得返回任何字节） | 公网侧实测 |
| AC5 | **不污染检索**：资源字节不进入 FTS 索引（`memory_search` 不得命中 `.png/.exe` 本体） | 检索断言 |
| AC6 | **登记幂等**：重复登记同一 sha256 资源不产生重复清单条目 | 单测 + 端到端 |
| AC7 | **资源服务仅内网可达**：服务不监听 `0.0.0.0` 的公网侧；104 防火墙不放行该端口到公网 | 端口与防火墙核对 |
| AC8 | **记忆库无回归**：`go test -count=1 ./cmd/... ./pkg/...` 全绿；公网阅读页与 MCP 行为不变 | 命令输出 |
| AC9 | **AI 使用说明**：清单内含「如何使用」段落（URL 模板、校验方式、公网限制），AI 读到即会用 | 清单文本核对 |

## 4. 明确不做

1. 不迁移记忆库（D6）；
2. 不做资源公网下载 / CDN / 对象存储；
3. 不引入前端框架、不改阅读页既有交互（资源上传的 Web UI 留待后续）；
4. 不做资源版本管理、回收站、权限分级（单口令模型不变）；
5. 不做大文件断点续传；
6. 不通过 MCP 传输二进制字节（**永远只传 ID + 元数据 + URL**）；
7. 不改 `memory/` 的目录结构与索引规则。

## 5. 边界与未知项

- **104 上的服务形态**（独立 Go 小服务 / 现有静态服务器）在 S2 定；需确认端口不冲突（已占用：22/3000/2222/8000/3389/5985）。
- **内网 DNS/主机名**：清单里用**固定 IP `192.168.7.104`**（设备档明确这是最可靠标识，MAC 为备用）。
- **清单与资源的一致性**：清单是"声明"，磁盘是"事实"；需提供一次"校验"命令（清单 → 磁盘逐一核对 sha256），S2 定形态。
- **磁盘增长**：645 GB 起步，不做配额；若后续吃紧再议。
- 资源区**不在记忆库 git 仓库内**，因此**无版本历史**，误删不可恢复（S2 需给出备份建议）。
