# DSH MCP 连接失败修复记录（2026-08-29）

> 现象：DSH 会话中 zipper-memory MCP 状态 failed（0 工具），「记忆库用不了」
> 服务器端检查全部正常（active、端口、索引 13 files、协议握手 200）

## 根因

DSH 的 MCP 客户端 `dsh-mcp-client-v2` 用 **MCP 2026-07-28 新协议**初始化
（`PROTOCOL_VERSION = '2026-07-28'`），但握手流程仍发送 `notifications/initialized`——
**该通知在新协议（2026-07-28）中已被移除**（SEP-2575）。

go-sdk v1.7.0 按规范正确拒绝：`method "notifications/initialized" is not supported in the new protocol`
→ 返回 HTTP 400 → DSH 将 zipper-memory 标记为 failed。

（注：我的 Python/Node 测试之前「成功」是因为用 2025-06-18 旧协议或不带 session；带 session + 2026-07-28 即复现 400）

## 修复

修改 DSH 客户端协议版本为旧协议（2025-06-18，支持 initialized 通知，服务器也接受）：

- 文件：`~/.dsh/profiles/web/node_modules/dsh-plugins/packages/dsh-mcp-client-v2/lib/mcp.js`
  （`profiles/web/node_modules/dsh-mcp-client-v2` 是 junction → dsh-plugins 真实文件）
- 改动：`PROTOCOL_VERSION = '2026-07-28'` → `'2025-06-18'`
- 备份：`mcp.js.bak-<时间戳>`（同目录）

## 生效条件

重启 DSH（`restart-dsh.ps1` 或手动）让新 bundle 加载。

## 遗留风险

- DSH 更新 mcp-client-v2 插件会覆盖 patch（junction 指向 dsh-plugins，需重新 patch）
- 更彻底方案：等 DSH 官方修复（新协议下跳过 initialized 通知），或在服务端兼容（不推荐：违反规范）
