# 公网 IP 漂移导致 MCP 403（2026-09-20）

> 现象：DSH 会话中 `zipper-memory` MCP 状态 failed（0 工具），「记忆库用不了」
> 结论：**服务端完全正常**；客户端出口公网 IP 变了，被 `allow_ips` 白名单拒绝 → 403
> ⚠️ 与 2026-08-29 的协议问题（`notifications/initialized`）**现象相同但根因不同**，别照旧方子抓药

## 根因

- 服务端白名单（`/opt/zipper-agent-memory/config.json`）：`["127.0.0.1", "120.228.126.4"]`
- 本机当前公网出口 IP：**`120.228.125.194`**（家庭宽带动态分配，`120.228.126.4` 是旧租约）
- `pkg/mcp/ipfilter.go` 是**精确 IP 匹配**（`netip.ParseAddr` + `Unmap` 归一的 map 查表，**不支持 CIDR 网段**），未命中即返回 403（`ipfilter.go:66`）

失败链路：403 → MCP `initialize` 握手失败 → DSH 客户端重连 10 次耗尽 → `state = failed`、已注册工具全部注销。

## 排查证据链（2026-09-20 11:08）

| # | 检查项 | 实测结果 |
|---|--------|---------|
| 1 | DSH MCP 状态 | `zipper-memory` → failed，0 工具 |
| 2 | 服务端服务 | `zipper-agent-memory.service` active running、监听 `*:8931`、索引 30 files |
| 3 | MCP 端点探测（本机） | POST initialize → **403 Forbidden**（TCP 8931 通，Ping 不通属正常） |
| 4 | 服务端白名单 | `allow_ips: ["127.0.0.1", "120.228.126.4"]` |
| 5 | 本机公网出口 IP | **120.228.125.194**（`ifconfig.me`） |
| 6 | 拒绝逻辑定位 | `pkg/mcp/ipfilter.go:58-71` Middleware → `http.Error(w, "403 forbidden: source IP not allowed", 403)` |
| 7 | 服务端启动日志 | `MCP IP allowlist enabled: 2 entry(ies)` |

### 顺手排除的怀疑（避免下次误判）

- ❌ **不是** 2026-08-29 那个协议问题：`desktop` 与 `web` 两个 profile 的 `dsh-mcp-client-v2` 的
  `PROTOCOL_VERSION` **均为 `2025-06-18`**，patch 仍在（未被 DSH 更新覆盖）
- ❌ 不是服务端进程 / 端口 / 索引故障
- ❌ 不是 DSH 配置 url 写错（`http://8.141.89.50:8931/mcp` 正确）
- ❌ `.dsh/restart-tailscale.ps1` 名字虽含 tailscale，实际只重启 DSH 桌面端，与本问题无关

## 修复（已执行 2026-09-20 11:10）

1. 备份：`/opt/zipper-agent-memory/config.json.bak-20260920-111032`
2. `allow_ips` 中 `120.228.126.4` → **`120.228.125.194`**
   （**替换而非追加**：旧 IP 已不在本机手中，保留等于给他人留门）
3. `systemctl restart zipper-agent-memory`
   - 结果：active；`MCP IP allowlist enabled: 2 entry(ies)`；`index ready: 31 files`
4. 验证
   - 服务器本地 `127.0.0.1` initialize → **200**
   - 从本机（即此前被拒的出口 IP）initialize → **200**，返回 `mcp-session-id: UDPBLQE3RWAHHWFMFDKYDA5FDH`、
     `serverInfo: zipper-agent-memoryd v0.4.0`、`protocolVersion: 2025-06-18`

## DSH 客户端需重载插件 / 重启 Host 才会重连（已闭环）

`dsh-mcp-client-v2` 的重连有上限（`reconnect.maxAttempts: 10`），耗尽后**不再自动重试**，
`index.js:489-503` 明确提示需 `reload the plugin or restart the Host`。

**本次决策：暂不重启 DSH**（避免中断当前会话），等下次自然重启时 MCP 自动恢复。

### 恢复验证（2026-09-20 11:12，用户重启 DSH 后）

| 验证项 | 结果 |
|--------|------|
| MCP 状态 | failed → **ready**，6 个工具全部注册 |
| `memory_status` | 203 files / 424770 bytes，`last_modified: 2026-09-20 00:05:51 CST` |
| `memory_search`（中文） | 正常命中 |
| 出口 IP 复核 | 仍为 `120.228.125.194`（与白名单一致，重启期间未再漂移） |

结论：**服务端改白名单 + 客户端重启 = 完全恢复**，根因定位准确。
全局记忆库已同步一份精简排查笔记：`notes/mcp-403-ip-allowlist.md`。

## 复发风险与对策（未实施，待决策）

白名单是**精确 IP**，家宽动态 IP 一变就会复发。可选对策：

| 方案 | 说明 | 代价 |
|------|------|------|
| A. 手动改 IP（本次采用） | 改 config.json + 重启服务，约 1 分钟 | IP 再变即复发 |
| B. SSH 隧道 | `ssh -N -L 8931:127.0.0.1:8931 minichat-server`，客户端连 `http://127.0.0.1:8931/mcp`；服务端只认 127.0.0.1，IP 漂移免疫（已在「DSH 接入指南」作为外出方案存在） | 需隧道常驻 |
| C. 客户端自动上报 IP | 新增机制，定期把公网 IP 同步进服务端白名单 | 开发量大 |
| D. 白名单支持 CIDR | 改 `ipfilter.go`（现为 `netip.ParseAddr` 单地址解析，需引入 `netip.Prefix` 匹配） | 安全性下降 |

## 复发时最快自查（约 30 秒）

```powershell
# 1) 本机当前公网出口 IP
Invoke-RestMethod https://ifconfig.me/ip

# 2) 直连 MCP 握手：403 = 白名单未命中；200 = 服务端正常（问题在 DSH 侧）
$body = '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"diag","version":"1.0"}}}'
try {
  (Invoke-WebRequest -Uri "http://8.141.89.50:8931/mcp" -Method POST -Body $body -UseBasicParsing -TimeoutSec 15 `
    -ContentType "application/json" -Headers @{ Accept = "application/json, text/event-stream" }).StatusCode
} catch { "HTTP " + [int]$_.Exception.Response.StatusCode }
```

判读：

- **403** → 第 1 步的 IP 与 `allow_ips` 不一致 → 按本文「修复」步骤改 IP 并重启服务
- **200 但 DSH 仍 failed** → 服务端没问题，是客户端重连已耗尽 → 重载插件或重启 DSH
