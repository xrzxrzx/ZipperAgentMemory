# MCP 访问改为 SSH 隧道根治 IP 漂移（2026-09-29）

> 背景：9 天内**第二次**因家宽公网 IP 漂移导致 MCP 403（见 `2026-09-20-公网IP漂移-MCP-403.md`）
> 决策：放弃「手动改白名单 IP」，改为**本机 SSH 隧道**接入 —— 服务端只认 `127.0.0.1`，与公网 IP 彻底解耦

## 为什么必须改方案

| 日期 | 本机公网出口 IP | 结果 |
|------|----------------|------|
| 2026-09-20 | `120.228.126.4` → `120.228.125.194` | 403（第一次） |
| 2026-09-29 | `120.228.125.194` → `120.228.125.157` | 403（第二次，仅隔 4 天） |

白名单是**精确 IP 匹配**（`pkg/mcp/ipfilter.go`，不支持 CIDR），家宽动态 IP 平均几天漂一次 →
手动救急只是拖延，不是修复。

## 方案

```
DSH ──► http://127.0.0.1:8931/mcp ──► [ssh -L 8931:127.0.0.1:8931] ──► 服务器 127.0.0.1:8931
        本机回环                       SSH 隧道（本机→8.141.89.50）      服务端只看到 127.0.0.1
```

服务端白名单原本就含 `127.0.0.1`，因此**服务端零改动**，公网 IP 怎么漂都不影响。

## 实施内容（本机侧）

| 组件 | 路径 | 作用 |
|------|------|------|
| 隧道监督者 | `~/.dsh/zipper-memory-tunnel.ps1` | while 循环保活 SSH 隧道；退出后 5s 重连；`Global\ZipperMemoryTunnel` Mutex 单实例；日志超 1MB 自动轮转 |
| 登录自启 | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\zipper-memory-tunnel.vbs` | 登录时**隐藏窗口**拉起监督者（无需管理员） |
| DSH 配置 | `~/.dsh/dsh-mcp-client-v2.json` | `url`：`http://8.141.89.50:8931/mcp` → **`http://127.0.0.1:8931/mcp`**；备份 `dsh-mcp-client-v2.json.bak-20260929` |
| 运行日志 | `~/.dsh/zipper-memory-tunnel.log` | 每次连接/断开/重连记录（含时间戳） |

SSH 参数：`-N -o BatchMode=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3`，
别名 `minichat-server`（`~/.ssh/config`，密钥认证，免密）。

### 为什么没用计划任务

`Register-ScheduledTask` 与 `schtasks /Create /SC ONLOGON` 在当前（未提权）会话下**均返回 Access is denied**，
故改用启动文件夹 + vbs 隐藏启动 —— 免提权、效果等价。

## 验证（2026-09-29 20:13–20:14）

| 步骤 | 结果 |
|------|------|
| 手动启动监督者 → 直连隧道握手 | **HTTP 200** |
| 杀掉监督者进程树 → 端口释放 | ✅ 端口已释放（确认无残留占用） |
| 运行 Startup 的 vbs（模拟登录） | 监督者自动拉起，端口重新监听（pid 7860） |
| 自启后再次握手 | **HTTP 200** —— **自启链路端到端可用** |
| DSH 配置 JSON 校验 | `JSON OK -> url = http://127.0.0.1:8931/mcp` |

## 运维手册

```powershell
# 隧道是否活着（应看到 127.0.0.1:8931 处于 Listen）
Get-NetTCPConnection -LocalPort 8931 -State Listen

# 最近连接记录
Get-Content "$env:USERPROFILE\.dsh\zipper-memory-tunnel.log" -Tail 20

# 手动重启隧道：杀掉监督者树，再跑一次 vbs 即可
Get-Process -Name ssh | Stop-Process -Force
wscript.exe "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\zipper-memory-tunnel.vbs"

# 端到端自检（200 = 通；非 200 = 隧道或服务器有问题）
$body = '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"diag","version":"1.0"}}}'
try { (Invoke-WebRequest -Uri "http://127.0.0.1:8931/mcp" -Method POST -Body $body -UseBasicParsing -TimeoutSec 15 -ContentType "application/json" -Headers @{ Accept = "application/json, text/event-stream" }).StatusCode } catch { "HTTP " + [int]$_.Exception.Response.StatusCode }
```

## 新的依赖点与权衡

| 项 | 说明 |
|----|------|
| 依赖 SSH 可达 | 隧道要求 8.141.89.50:22 可达；22 端口若不通则隧道不可用（公网直连反而仍可用） |
| 新增本机进程 | 一个常驻 powershell 监督者 + 一个 ssh 进程（资源占用极小） |
| DSH 配置被改 | `url` 指向回环；若隧道未运行，MCP 会连接被拒而非 403 |
| 已获得的好处 | 公网 IP 漂移免疫；外出（非家庭网络）同样可用；服务端无需再改 |
