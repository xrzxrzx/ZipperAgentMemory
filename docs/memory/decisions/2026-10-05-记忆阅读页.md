# 决策记录：记忆阅读页（只读 Web UI）上线（2026-10-05）

> 依据：用户直接指令（2026-10-05「给服务器加一个阅读我自己记忆库的页面，需要 token 不过期」）
> 关联：`docs/design.md §11` + §10 决策 8；`docs/features/需求-001-记忆阅读页/`；提交 `4c742f0` / `789d1d4` / `17428ad` / `53ac71e` / `32cad7f`

## 背景

记忆库此前只能通过 MCP / CLI（SSH 隧道 + 客户端配置）访问，**手边只有浏览器时看不到自己的资料**。
用户提出：加一个阅读页，需要输入 token（长期有效）才能读。

调研取证（`调研.md §3`）发现三件事改变了原始设想：

1. **`memory.zipper.net.cn` 不存在**（DNS NXDOMAIN、无泛解析），且现有证书 SAN 只覆盖 `zipper.net.cn` / `www.zipper.net.cn` → 建子域需另签证书；
2. `zipper.net.cn` 的 HTTPS vhost 自 2026-09-20 起**被禁用**，443 未监听；
3. 守护进程只有 `/mcp` 一个路由 + IP 白名单，**没有 token 概念**。

## 决策

| # | 决策 | 内容 |
|---|---|---|
| 1 | **入口形态** | 用户选定**路径式** `https://zipper.net.cn/memory/`（复用现有证书，不新建子域、不新签证书） |
| 2 | **暴露面** | 用户选定「只开 `/memory/`，其余路径 404」——主域首页**保持下线**，不启用既有 `zipper-net-ssl.conf.disabled` |
| 3 | **口令** | 单一**长期有效**口令（32 字节随机 base64url，43 字符），存服务器独立文件 `web-token`（0600）；**只能来自文件**，不支持 flag（避免 `ps` 泄露） |
| 4 | **凭据通道** | 持久 Cookie（HttpOnly/SameSite=Lax，HTTPS 下 Secure，Max-Age 10 年）+ `Authorization: Bearer`。<br>**为什么必须用 Cookie**：浏览器顶层导航不发送 Authorization 头，纯 Bearer 一刷新即掉登录 |
| 5 | **读取范围** | **全库可读**（含 `structured/` 密码资料）——用户明确知情并接受"口令是全库唯一防线"这一残余风险 |
| 6 | **只读** | 不提供任何写接口；写仍走 MCP / CLI |
| 7 | **搜索语义** | 多关键词由「整串连续短语」改为「按空白切分的词元 AND/OR」——修复用户报告的"多词搜不到"（实测 `隧道 端口` 由 0 命中 → AND 2 命中 / OR 9 命中） |
| 8 | **进程形态** | 与 MCP **同进程**、独立监听 `127.0.0.1:8932`（复用同一 store/index，守住 60MB 内存红线：实测 RSS 19.1MB） |

## 理由

- 路径式入口把"新增域名 + 新证书 + 安全组"三件事压缩成零，最快可用且不增加证书运维面；
- 只开 `/memory/` 把主域从"占位首页"状态保持下线，暴露面最小；
- Cookie + Bearer 双通道是"浏览器能用 + 脚本能用"的最小实现；
- 服务端 goldmark 渲染（**不启用 `WithUnsafe`**）：库内存在从外部抓取的资料，客户端 `innerHTML` 直渲染会执行其中的脚本。

## 后果

**得到**：浏览器随时可读全库；多关键词检索可用；口令长期有效、可一键轮换；访问日志不含口令与检索词。

**付出与残余风险**：

| 项 | 说明 |
|---|---|
| 口令即全库 | 泄露 = 密码资料泄露。缓解：仅 HTTPS、HttpOnly+Secure Cookie、32B 随机、失败限流、日志脱敏；**处置：`web-token -init -force` + 重启 + 改库内密码** |
| 反代下限流退化 | nginx 后所有来源都是 `127.0.0.1`，"每 IP 10 次/分钟"实为**全局单桶**——任意可达者可让所有者 60 秒内无法**新登录**（已登录会话不受影响）。**待用户决策**（可信 XFF / 放宽阈值 / 维持现状） |
| 新增依赖 | `github.com/yuin/goldmark`（纯 Go、MIT、无 CGO） |
| `memory_search` 契约变更 | 多词语义由"连续短语"改为"AND 词元"（单词查询不变）；新增可选 `mode` 参数 |
| 点目录可见 | `tree`/`file` 不隐藏 `.git/` 等点目录，全库可读包含仓库内部；**待用户决定是否隐藏** |

## 部署与验证

- 生产部署按变更单四件套执行（备份逐字节验证 → 原子替换 → 口令生成 → 配置 → 重启 → `nginx -t` + reload → 双视角验收 → 10 分钟观察），记录见 `docs/features/需求-001-记忆阅读页/验收.md §1.4`；
- **独立验证（审查者 ≠ 作者）**：无 P0/P1，5 项 P2、10 项 P3；P2-1/2-2/2-3/2-5 与 5 项 P3 已当场修复并加回归用例；
- 部署过程中口令曾因打印 `Set-Cookie` 整行而进入会话记录 → **当场按 R4 轮换**，复核旧口令 401 失效（教训：Cookie/口令类响应头一律脱敏后再落证据）。
