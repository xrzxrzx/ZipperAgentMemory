# DSH 升级 2.0.20-next 后 MCP 配置迁移（2026-10-27）

> 现象：DSH 里 `zipper-memory` 的 MCP 工具**全部消失**（连 `mcp_tool_search` 都不存在），
> 但服务器 `zipper-agent-memory` 与 SSH 隧道、隧道握手（HTTP 200）全部正常。
> 根因：DSH 大版本升级把 MCP 客户端**内置化并改名**，配置方式由独立 JSON 改为 cordis 配置条目。

## 新旧对照

| | 旧版 2.0.11 | 新版 2.0.20-next |
|---|---|---|
| MCP 客户端 | 外部插件 `dsh-mcp-client-v2`（0.2.0） | **内置** `@deepseek-ai/dsh-mcp-client` |
| 配置位置 | `~/.dsh/dsh-mcp-client-v2.json` | `~/.dsh/profiles/<profile>/cordis.patch.yml` 的配置条目 |
| `dsh-settings-compat` | 外部插件 | **不再需要**（已并入内核） |

证据：`app.asar` 中 `dsh-mcp-client-v2`、`dsh-settings-compat` 均搜不到，而 `dsh-mcp-client` 存在；
旧配置文件名 `dsh-mcp-client-v2.json` 在新版 asar 里也搜不到（说明根本不读）。

## 失效时间线（2026-10-27）

```
06:34  安装 DSH NEXT 2.0.20-next
15:40  启动 → 旧外部插件仍从 node_modules 加载，MCP 正常（6 工具）
15:41  插件管理器重装依赖 → pnpm 修剪掉不在 dependencies 里的旧包
15:43  配置重载 → 旧插件消失，新内置插件无配置条目 → MCP 工具全部消失
```

## 修复

在 `~/.dsh/profiles/desktop/cordis.patch.yml` 末尾追加（新版 schema 来自 asar 内
`@deepseek-ai/dsh-mcp-client` 的 README）：

```yaml
- insert:
    - id: mcp-zipper-memory
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: zipper-memory
        transport: streamable-http
        url: http://127.0.0.1:8931/mcp      # 走本机 SSH 隧道，见 2026-09-29 记录
        toolCallTimeoutMs: 60000
    - id: mcp-playwright
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: playwright
        transport: stdio
        command: 'D:\Program Files\nodejs\node.exe'
        args:
          - 'C:\Users\xrzxr\.dsh\mcp-servers\playwright\node_modules\@playwright\mcp\cli.js'
          - '--browser'
          - 'msedge'
          - '--user-data-dir'
          - 'C:\Users\xrzxr\.dsh\browser\zipper-profile'
          - '--idle-timeout'
          - '600000'
        toolCallTimeoutMs: 120000
```

**DSH 检测到 patch 变更后自动热重载，无需重启。**

## 教训

1. **DSH 升级会改插件体系**：`bundles` 里声明的外部插件可能被内置替代，升级后必须核对
   `cordis.patch.yml` 是否仍匹配新版 schema。
2. **旧配置文件不会自动迁移**：`dsh-mcp-client-v2.json` 在新版里已不被读取，留着也不会生效。
3. **pnpm 重装会修剪**"不在 dependencies 里"的包——旧外部插件正是这样消失的。
4. **排查顺序**：先确认服务器与隧道（本次均正常）→ 再查 DSH 侧插件与配置 → 最后才怀疑协议。
5. 新版 MCP 配置字段：`serverName`（`[A-Za-z0-9_-]{1,32}`、同作用域唯一）、`transport`
   （`stdio` / `streamable-http`）、`command`/`args`/`env`/`cwd`、`url`/`headers`、
   `toolCallTimeoutMs`（默认 60000）、`maxInstructionBytes`（默认 32768）。
