## 决策 1：MCP 传输形态（design.md §4.1）

**推荐：方案 A —— 单常驻进程 + streamable HTTP**

| 考量 | 方案 A（推荐） | 方案 B | 方案 C |
|------|---------------|--------|--------|
| 符合「常驻进程」需求 | ✅ 真常驻 | ✅ 常驻（但多一进程） | ❌ 无常驻 |
| 进程数/内存 | 1 个（最优） | 2 个 | 1 个（按需拉起） |
| 索引热更新 | ✅ 永远热 | ✅ | ❌ 无连接时不维护 |
| 客户端兼容 | 主流客户端均支持 HTTP（2026 现状） | 纯 stdio 兼容 | stdio 原生 |
| 复杂度 | 低 | 高 | 最低 |

**一句话**：你要的是「服务器常驻进程维护记忆」，方案 A 是唯一同时满足「真常驻 + 单进程 + 索引永热」的；一个二进制两种模式（`serve` 常驻 HTTP / `stdio` 按需）保留 stdio 兼容性。

👉 **如无异议，选 A**

## 决策 2：git autocommit 默认开关（design.md §8 阶段 4）

**推荐：默认关闭**（代码做成开关，随时可开）

- 记忆永久性靠「文件本身 + 迁移备份」保证，git 是额外保险丝；
- 默认开启会让低配服务器频繁跑 git 进程，且仓库膨胀快；
- 想要历史保护时可显式开启（`--git-autocommit` 或配置文件）。

👉 **如无异议，默认关闭**
