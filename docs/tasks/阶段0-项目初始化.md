# 任务书（草稿）：阶段 0 —— 项目初始化

> 状态：**草稿，待设计文档批准后生效**。批准后由协调者派发给编码子 Agent。

## 任务书：阶段 0 项目初始化

- **派发者**：协调者
- **依据**：`docs/design.md` §8 阶段 0；`docs/standards/go-编码规范.md`；`AGENTS.d/*`
- **目标**：建立可编译的 Go 模块骨架，为阶段 1 提供工程基础
- **范围**：
  - 初始化 Go 模块（`go mod init`，模块名建议 `github.com/xrzxrzx/ZipperAgentMemory` 或 `zipper-agent-memory`，由协调者定）
  - 建目录骨架：`cmd/zipper-agent-memoryd/`、`pkg/memory/`、`pkg/index/`、`pkg/mcp/`、`internal/`（按需）
  - `go.mod` 锁定 Go ≥1.25；暂不引入第三方依赖（阶段 1 再加）
  - 空实现入口 `main.go`（打印版本号即可），保证 `go build ./...` 通过
  - Makefile（build/test/run 目标）
  - **不做**：任何业务逻辑、索引、MCP 工具（阶段 1+）
- **验收标准**：
  - `go build ./...` 零错误、零 vet 告警
  - `go test ./...` 通过（允许 0 测试但必须有可运行骨架）
  - 二进制运行输出版本信息后正常退出
  - 目录结构与设计文档 §8 一致
- **交付物**：`go.mod`、`cmd/`、`pkg/` 骨架、`Makefile`、`main.go`
- **约束**：遵守 `docs/standards/go-编码规范.md`（gofmt、命名、错误处理）；不引入未经批准的第三方依赖；提交用 Conventional Commits（`chore: 初始化Go模块骨架` 或 `feat:` 视内容）
- **DoD**：`go build ./... && go vet ./... && go test ./...` 全绿，产出截图/输出留档
