## 任务书：阶段 2 守护进程（watcher + 索引）

- **派发者**：协调者
- **依据**：`docs/design.md` §4（架构）、§8 阶段 2、§9 R7（derived state）；`docs/standards/go-编码规范.md`；`AGENTS.d/coding.md`
- **目标**：实现常驻守护进程核心：文件监听 + SQLite FTS5 索引，满足资源红线
- **前置**：阶段 1 已交付 `pkg/memory`（依赖其路径沙箱与 Store）
- **范围**：
  - `pkg/index`：SQLite FTS5 索引（`modernc.org/sqlite` 纯 Go，**WAL 模式**）
    - 索引内容：文件路径、mtime/size、front-matter 元数据（tags/created/source）、正文（FTS5）
    - 增量更新：`Upsert(path)` / `Remove(path)`
    - 全量重建：`Rebuild(store)`（遍历 memory/，供 `--rebuild-index`）
    - 搜索：`Search(query, limit)` → 路径 + 命中片段
  - `pkg/watch`：`fsnotify` 监听 + **去抖合并**（time.Ticker 窗口，防逐事件 IO）
    - 事件 → 增量索引更新；删除事件 → 索引移除
    - 目录树递归监听；新建/删除子目录的处理
  - `cmd/zipper-agent-memoryd`：
    - `serve`：启动 watcher + 索引（常驻，信号优雅退出：SIGTERM/SIGINT）
    - `rebuild-index`：全量重建后退出
    - `search "query"`：CLI 搜索（供人工/测试）
  - **不做**：MCP（阶段 3）、git autocommit（阶段 4）
- **验收标准**（每项留证据）：
  1. 修改文件后 **≤2s** 搜索可见新内容（去抖窗口内）；
  2. 搜索命中正确（关键词/中文）；删除文件后索引同步移除；
  3. `--rebuild-index` 后搜索结果与增量索引一致；
  4. **常驻内存 < 60MB**：`/usr/bin/time -v` 或 RSS 实测记录在案（阶段 2 红线验收）；
  5. 空闲 CPU ≈0（事件驱动，无轮询）；
  6. `go test ./...` 全绿、`go vet ./...` 零告警。
- **交付物**：`pkg/index/*`（含测试）、`pkg/watch/*`（含测试）、`cmd/zipper-agent-memoryd/`、资源实测记录
- **约束**：
  - 新增依赖 `modernc.org/sqlite`、`fsnotify` 已列入设计 §3.2，**不得再加其他第三方依赖**；
  - 索引是 derived state：**禁止**为索引一致性加锁/加事务强一致（R7），可随时 rebuild；
  - 遵守编码规范；提交 `feat(index): ...`、`feat(watch): ...` 等 Conventional Commits
- **DoD**：6 项验收标准全部通过且证据留档（`docs/验收/阶段2.md` 由协调者汇总）
