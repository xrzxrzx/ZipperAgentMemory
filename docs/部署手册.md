## 1. 前置条件清单（部署前逐项确认）

### 1.1 服务器需安装/具备

| # | 项 | 要求 | 安装方式 | 备注 |
|---|----|------|----------|------|
| 1 | git | ≥ 2.x | `dnf install -y git` | autocommit 与 bundle 迁移必需 |
| 2 | Go 工具链 | **≥ 1.25**（go-sdk v1.7.x 要求；go.mod 声明 go 1.26） | 官方 tarball → `/usr/local/go`（版本固定可复现）或 `dnf install golang` | 服务器原生编译用；也可用本机交叉编译产物跳过 |
| 3 | bash | 已有（al8 默认） | — | `scripts/migrate.sh` 依赖 |
| 4 | tar | 已有 | — | migrate.sh pack/restore 主路径 |
| 5 | zip/unzip | **缺失** | `dnf install -y zip unzip`（可选） | 仅 migrate.sh 的 zip 回退分支用；主路径为 tar |
| 6 | sqlite3 CLI | 已装 | — | 可选，人工查索引用 |
| 7 | 磁盘余量 | ≥ 100MB | — | 二进制 ~15MB + memory 内容 + 索引 |
| 8 | 端口 8931 | 未被占用 | `ss -ltn | grep 8931` | 默认监听地址 |

### 1.2 网络前置

- **Go 模块代理**：`proxy.golang.org` 需可达（评估时 HTTP 200 ✅）；若服务器无法直连，设置 `GOPROXY` 指向可用镜像或离线 `go mod vendor`；
- **GitHub**：`git clone https://github.com/xrzxrzx/ZipperAgentMemory.git`（或 SSH）。评估风险：服务器上 22 端口可能被墙，需与本地一致走 **SSH over 443** 通道，或改走 HTTPS，或**本地打包上传**（`tar czf` 源码 → `scp`）绕过 GitHub——三种方式任选，部署时实测连通性后决定。

### 1.3 需用户确认的事项（部署执行前）

| # | 事项 | 默认 | 说明 |
|---|------|------|------|
| 1 | 安装路径 `/opt/zipper-agent-memory` | ✅ | 可改 |
| 2 | 监听地址 `127.0.0.1:8931` | ✅ | MCP 客户端与守护进程**同机**访问（客户端跑在服务器上时无需改）。若客户端需远程访问，改 `-addr 0.0.0.0:8931` 或内网 IP，**必须配置 `-allow-ips` IP 白名单**（工具可写文件，公网裸奔高风险；design §10 决策 6，配合防火墙/SSH 隧道更佳） |
| 3 | git autocommit 是否开启 | 开（默认，每日 0 点定时提交一次） | design §10 决策 3（2026-08-22 变更）：autocommit **默认开启**，每日 0 点自动 git add -A && commit 一次；可随时 `git-commit` 子命令主动提交；需关闭时 `-git-autocommit=false` |
| 4 | git 本地身份 | `zipper-agent-memory` / `zipper-agent-memory@localhost` | `git-init` 自动补全本地 config，不碰全局；可在 memory/ 内覆盖 |
| 5 | 首次数据来源 | 空库 或 迁移导入（pack 包 / bundle） | 见 §7 |
| 6 | systemd `MemoryMax=60M` 是否启用 | 可选（默认注释） | 内存红线 <60MB，但重建索引瞬间可能略高，过低会 OOM-kill；建议实测后按需放开 |
| 7 | 部署方式 | 服务器原生编译 | 需装 Go；或本机交叉编译产物上传（§3 备选） |

## 2. 从零到跑通（标准路径）

### 步骤 1：安装基础工具

```bash
# root 或 sudo
dnf install -y git
# 可选：zip 回退分支
dnf install -y zip unzip
```

### 步骤 2：安装 Go ≥ 1.25（服务器原生编译路径）

```bash
# 推荐官方 tarball，版本固定可复现（以 1.26.x 为例，按需替换版本号）
cd /tmp
curl -LO https://go.dev/dl/go1.26.7.linux-amd64.tar.gz
rm -rf /usr/local/go && tar -C /usr/local -xzf go1.26.7.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin' >> /etc/profile.d/go.sh
export PATH=$PATH:/usr/local/go/bin
go version   # go1.26.7 linux/amd64
```

> 备选：`dnf install golang`（版本可能滞后，需确认 ≥1.25）。
> 若选择本机交叉编译产物（§3 备选），本步骤可跳过。

### 步骤 3：获取代码

```bash
mkdir -p /opt && cd /opt
# 方式 A：GitHub clone（22 端口被墙时改 SSH over 443 或 HTTPS）
git clone https://github.com/xrzxrzx/ZipperAgentMemory.git zipper-agent-memory
# 方式 B：本地源码打包上传（绕过 GitHub 连通性问题）
#   本机：tar czf zipper-agent-memory-src.tgz --exclude='.git' --exclude='bin' D:\Works\ZipperAgentMemory 内容
#   scp 上传后解压到 /opt/zipper-agent-memory
cd /opt/zipper-agent-memory
```

### 步骤 4：构建（服务器原生编译）

```bash
cd /opt/zipper-agent-memory
export PATH=$PATH:/usr/local/go/bin
go build -o /usr/local/bin/zipper-agent-memoryd ./cmd/zipper-agent-memoryd
go build -o /usr/local/bin/zam ./cmd/zam
# 冒烟验证
/usr/local/bin/zipper-agent-memoryd version    # zipper-agent-memoryd v0.4.0
```

> 备选（本机交叉编译，零 CGO）：在开发机执行
> `GOOS=linux GOARCH=amd64 go build -o zipper-agent-memoryd-linux-amd64 ./cmd/zipper-agent-memoryd`
> 上传到 `/usr/local/bin/zipper-agent-memoryd` 并 `chmod +x`。本项目 SQLite 用 `modernc.org/sqlite`（纯 Go），**交叉编译无 CGO 障碍**。

### 步骤 5：初始化记忆库（空库场景）

```bash
# 项目自带 memory/ 骨架；初始化为 git 仓库（autocommit/bundle 前置，幂等）
/usr/local/bin/zipper-agent-memoryd git-init -root /opt/zipper-agent-memory/memory
# git-init: repository ready at /opt/zipper-agent-memory/memory
```

### 步骤 6：systemd 托管常驻进程

创建 `/etc/systemd/system/zipper-agent-memory.service`：

```ini
[Unit]
Description=ZipperAgentMemory memory daemon (MCP server)
# 需要网络可达（HTTP 绑定 + autocommit 默认开启但不依赖外网，保持声明）
Requires=network.target
After=network.target

[Service]
Type=simple
User=root
# 工作目录指向项目根（-root 为绝对路径，此值仅影响相对路径解析）
WorkingDirectory=/opt/zipper-agent-memory
# 常驻 serve：全量重建索引 → fsnotify 增量维护 → MCP streamable HTTP
# autocommit 默认开启：独立 goroutine 每日 0 点定时提交一次（design 决策 3）；
# 需关闭时加 -git-autocommit=false。
# 公网部署（决策 6）：-addr 0.0.0.0:8931 时必须配 -allow-ips 白名单，例如：
#   ExecStart=/usr/local/bin/zipper-agent-memoryd serve -root /opt/zipper-agent-memory/memory -addr 0.0.0.0:8931 -allow-ips "1.2.3.4,5.6.7.8"
# 推荐用配置文件承载白名单与 autocommit（见步骤 6b）：
#   ExecStart=/usr/local/bin/zipper-agent-memoryd serve -root /opt/zipper-agent-memory/memory -addr 0.0.0.0:8931 -config /opt/zipper-agent-memory/config.json
ExecStart=/usr/local/bin/zipper-agent-memoryd serve -root /opt/zipper-agent-memory/memory -addr 127.0.0.1:8931
# 崩溃自动拉起；连续失败 5 次后退避
Restart=on-failure
RestartSec=3
# 可选：内存红线（design §3.3 <60MB）。实测后按需调整；
# 注意重建索引瞬间内存可能高于常驻值，设得过低会被 cgroup OOM-kill
# MemoryMax=60M

[Install]
WantedBy=multi-user.target
```

启用并验证：

```bash
systemctl daemon-reload
systemctl enable --now zipper-agent-memory
systemctl status zipper-agent-memory --no-pager
journalctl -u zipper-agent-memory -n 20 --no-pager
# 期望日志：index ready: N files ... → MCP server listening on http://127.0.0.1:8931/mcp
```

### 步骤 6b：配置文件（可选，推荐公网部署用）

IP 白名单与 autocommit 可写入 JSON 配置文件，用 `-config <path>` 指定（不重编译，改文件重启即生效）：

```bash
cat > /opt/zipper-agent-memory/config.json <<'EOF'
{
  "autocommit": {"enabled": true, "hour": 0},
  "allow_ips": ["127.0.0.1", "120.228.126.4"]
}
EOF
```

字段全部可选，缺省用默认值：

| 字段 | 默认 | 说明 |
|------|------|------|
| `autocommit.enabled` | `true` | 每日定时提交开关（决策 3 默认开启） |
| `autocommit.hour` | `0` | 每日提交小时 0-23（0 = 每日 0 点） |
| `allow_ips` | `[]`（不限制） | MCP IP 白名单；空数组/缺失 = 不限制（本地模式无感知） |

**优先级**（从高到低）：flag 显式给出（`-allow-ips` / `-git-autocommit` / `-git-autocommit-hour`）> 配置文件 > 默认值。例：`-config` 配了 `allow_ips` 但命令行又给了 `-allow-ips "1.2.3.4"`，以 flag 为准；两者都未给则不限制。

- IP 变化：编辑 `config.json` 后 `systemctl restart zipper-agent-memory` 即可（白名单**启动时读取**，无需重编译）；
- 配置文件不存在 / JSON 非法 / hour 越界 / IP 非法：serve **启动即失败**（快速失败，日志见 stderr，不静默带病运行）；
- 启动日志会打印 `loaded config from <path>` 与生效值（`git autocommit enabled: daily commit at HH:00 local`、`MCP IP allowlist enabled: N entry(ies)`），可用 `journalctl` 核对。

### 步骤 7：首次索引与搜索验证

`serve` 启动时**自动全量重建索引**，一般无需手动；验证：

```bash
/usr/local/bin/zipper-agent-memoryd search -root /opt/zipper-agent-memory/memory "关键词"
curl -s -X POST http://127.0.0.1:8931/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"smoke","version":"0.1"}}}'
```

> 若怀疑索引与磁盘不一致（崩溃、手动改文件等）：`zipper-agent-memoryd rebuild-index -root /opt/zipper-agent-memory/memory`（derived state，随时可重建）。

### 步骤 8：MCP 客户端接入

守护进程已常驻，客户端配置指向 HTTP（方式 A）；或配置 stdio 按需拉起（方式 B）。完整示例见 `README.md`「MCP 客户端接入」。

- **方式 A（HTTP，推荐常驻场景）**：客户端 `url` 填 `http://127.0.0.1:8931/mcp`——客户端须与守护进程**同机**（127.0.0.1 绑定）；若 MCP 客户端运行在另一台机器，需改 `-addr` 并加 `-allow-ips` IP 白名单（或 SSH 隧道）；
- **方式 B（stdio 按需）**：`command: "/usr/local/bin/zipper-agent-memoryd"`，`args: ["stdio", "-root", "/opt/zipper-agent-memory/memory"]`；
- 验证：客户端 tools/list 应列出 6 个 `memory_*` 工具；调用 `memory_status` 返回文件数/字节/最近修改。
- **主动提交（决策 3）**：autocommit 每日 0 点自动提交一次，无需人工干预；需要立即固化当前变更时运行
  `zipper-agent-memoryd git-commit -root /opt/zipper-agent-memory/memory`（无变更时输出跳过）。

### 步骤 9：迁移导入（首次数据来自旧环境时）

在旧环境打包（见 README「迁移指南」），把产物传到服务器 `/tmp`，再还原：

```bash
# 目录打包模式（纯文件）
/opt/zipper-agent-memory/scripts/migrate.sh restore /tmp/memory.tar.gz /opt/zipper-agent-memory/memory --rebuild-index

# git bundle 模式（完整历史；还原目录必须不存在或为空）
/opt/zipper-agent-memory/scripts/migrate.sh restore /tmp/memory.bundle /opt/zipper-agent-memory/memory --rebuild-index

# 验证
/usr/local/bin/zipper-agent-memoryd search -root /opt/zipper-agent-memory/memory "旧库关键词"
systemctl restart zipper-agent-memory   # 让常驻进程基于新库重建索引并继续监听
```

> 还原会**替换** memory/ 内容，执行前确认目标目录为空/可覆盖；还原后重启 systemd 服务使常驻进程的索引与监听指向新库。

## 4. 运维要点

- **日志**：`journalctl -u zipper-agent-memory -f`（serve 日志全部走 stderr；每日 0 点定时提交触发时输出 `git: daily commit trigger (scheduled 00:00)` 与提交/跳过结果）；
- **autocommit**：默认开启，每日定时提交一次（默认 0 点，`-git-autocommit-hour` 或配置 `autocommit.hour` 可调，design 决策 3）；可随时 `zipper-agent-memoryd git-commit -root ...` 主动提交；需关闭时 `-git-autocommit=false` 或配置 `autocommit.enabled=false`；
- **公网访问**：`-addr` 非 loopback 时务必配置白名单（design 决策 6）——白名单外的请求一律 403；白名单为空时不限制（本地模式无感知）。白名单来源：`-allow-ips` flag（显式优先）或 `-config` 配置文件的 `allow_ips`；**改文件后 `systemctl restart` 生效**；
- **配置**：`-config <path>` JSON 配置文件承载 autocommit/allow_ips（见步骤 6b）；flag 显式给出时优先；配置缺失字段用默认值；配置文件损坏时启动快速失败；
- **升级**：停服务 → 替换二进制 → `systemctl start`（索引随启动自动重建，无需手工迁移）；
- **备份**：记忆文件即真源，备份 `memory/`（目录复制或 git push/bundle）；索引库 `.zipper-agent-memory.index.sqlite*` 是 derived state，**无需备份**（可随时 rebuild）；
- **git gc**：仓库随记忆增长膨胀时手动 `git gc`（进程只提示从不自动执行，design R4）；
- **迁移**：见 README「迁移指南」与脚本帮助 `./scripts/migrate.sh help`。

## 6. 前置条件清单（汇总版，给用户确认）

1. **服务器操作授权**：以 root 安装 git / Go、写入 `/opt`、创建 systemd unit——需用户授权本次部署会话；
2. **部署路径**：`/opt/zipper-agent-memory`（可改）；
3. **监听策略**：默认 `127.0.0.1:8931`（同机客户端）；远程访问需 `-addr` + **IP 白名单**（决策 6，`-allow-ips` 或 `-config` 配置文件 `allow_ips`）/ SSH 隧道；
4. **autocommit**：默认开启（每日定时提交一次，默认 0 点，决策 3）；随时可用 `git-commit` 主动提交；如需关闭告知（`-git-autocommit=false` 或配置 `autocommit.enabled=false`）；
5. **首次数据**：空库起步，还是导入现有记忆（pack 包 / bundle 文件路径）；
6. **MemoryMax=60M**：是否启用（默认注释，实测后按需放开）；
7. **git 身份**：默认本地身份 `zipper-agent-memory@localhost`，如需自定义在 memory/ 内 `git config --local` 覆盖。
