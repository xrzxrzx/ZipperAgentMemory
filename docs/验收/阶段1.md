## 6. 偏离与注意事项

1. **发现并修复 Windows junction 逃逸漏洞（重要）**：按规范 §5.1 用 `filepath.EvalSymlinks` 实现时，实测发现 Windows 上 EvalSymlinks **不解析 junction**（对 junction 返回原路径、对 junction 内文件报错），导致 `zam write evil-junc/new.md` 曾成功穿出根目录写文件。修复：改用**组件级 `Lstat + os.Readlink` 解析**（Readlink 对符号链接与 junction 都返回目标路径），并在 `OpenStore` 中同样用该机制解析根目录；加 255 层递归上限防链接环。Linux 上对符号链接行为与 EvalSymlinks 一致，属其超集。此偏离已记录在代码注释（memory_store.go `resolvePath`），不影响设计意图（§6.2「路径必须落在 memory/ 根内」）。
2. **测试正则首轮失败**：append 时间戳正则最初未计入 RFC3339 时区后缀（`+08:00`），修正后通过；与实现无关。
3. **go 命令不在沙箱 PATH**：延续阶段 0 结论，全部命令显式前置 `C:\Users\xrzxr\sdk\go1.26.7\bin`。
4. **Makefile 增加 `zam` 目标**（`make zam` 构建 bin/zam）：超出任务书交付清单的小便利项，已记录。
5. **演示产物已清理**：CLI 实测产生的 `memory/notes/test.md`、`memory/agent/dev/` 在取证后删除，`memory/` 骨架保持与 design.md §5 一致的 9 个文件；删除操作已在上文证据中体现，不影响验收有效性。
6. **未执行任何 git 命令**：按任务书由协调者统一提交（建议 `feat(memory): 记忆库文件读写核心` + `docs(验收): 阶段1` 分型提交）。
7. **待 Linux 验证**：路径沙箱组件级解析与原子写（含目录 fsync）的等价性，建议阶段 2 在目标 Linux 环境复跑 `go test ./...` 确认。
