## 4. 偏离与注意事项

1. **官方 go-sdk 实际 API 与调研报告的差异**（交付要求注明）：
   - 调研报告描述的 `mcp.NewServer + AddTool(typed) + Run(StdioTransport)` 在 v1.7.0 属实；但本项目工具注册采用**原始 `Server.AddTool` + `json.RawMessage` 输入 schema + 手动参数校验**，而非泛型 typed `AddTool[In,Out]`：原始路径让我们完全控制错误消息（结构化 MCP 错误区分缺参/非法参/穿越），且不依赖 jsonschema-go 对 required/default 的推断行为。成本是手写每个工具的 schema 与校验（工具仅 6 个，可控）。
   - `ToolAnnotations`：`DestructiveHint`/`OpenWorldHint` 为 `*bool`，`ReadOnlyHint`/`IdempotentHint` 为 bool（调研已预告的 rough edge，v1.7.0 现状）。
   - 错误语义：工具执行错误（穿越/不存在/已存在）一律 `CallToolResult.IsError=true` + Content 文本（SDK 规范：LLM 可见可自纠正），不上升为 JSON-RPC 协议错误；只有未知工具等协议异常走协议错误。
   - streamable HTTP 是 **stateful**（`Mcp-Session-Id` 会话头，initialize 响应携带，后续请求必须回传）；不传则每次 POST 都是新会话、tools/list 返回空。服务端配置 `JSONResponse: true`：单消息 POST 直接返回 `application/json`（默认是 SSE 帧），便于 curl/PowerShell 等命令行客户端调试——这是 SDK 文档化选项，非协议偏离。
   - 2026-07-28 规范下 `server/discover` 可用，但 legacy `initialize`（protocolVersion 2025-11-25）经自动协商完整可用；e2e 走 legacy 流程验证。
2. **Windows vs Linux 差异**：
   - `go test -race` 需 cgo（本机 CGO_ENABLED=0），未跑；Linux CI 可补（pkg/memory 与 pkg/mcp 并发逻辑一致，均为 Store 锁内串行）。
   - junction 逃逸测试 Windows 用 `cmd mklink /J`（无需管理员）；Linux 无 junction 语义，符号链接逃逸由 pkg/memory 既有测试覆盖（阶段 1），MCP 层复用同一沙箱。
   - 目录 fsync 在 Windows 静默忽略（阶段 1 已处理）；stdio 协议日志走 stderr，stdout 纯净（Windows/Linux 一致）。
   - 验证脚本注意：PowerShell 5.1 写 UTF-8 文件默认带 BOM，JSON-RPC 输入会被 SDK 拒绝（报 `invalid character 'ï'`），验证脚本须显式无 BOM 写入；Python subprocess 在 Windows 紧时序「写→读→写」偶发管道怪癖（加 0.3s 间隔即稳定），Go exec 管道（真实客户端模式）无此问题——均为验证脚本环境问题，非服务端缺陷。
3. **默认端口**：`serve -addr` 默认 `127.0.0.1:8931`（任务书「如 8931」确认），挂载路径 `/mcp`（design.md §4.1：`http://127.0.0.1:8931/mcp`）。
4. **写后索引同步**：`memory_write`/`memory_append` 成功后由 `indexFile` 同步更新索引（设计文档 §6.2 写入顺序「临时文件 → rename → 索引」的进程内实现），搜索立即一致；索引失败只记 stderr 日志，watcher（事件驱动）与 `--rebuild-index` 均可恢复（§9 R7，索引是 derived state）。
5. **stdio 模式无 watcher**：按需拉起进程在启动时全量 Rebuild 一次后仅服务 MCP（会话期短、进程随客户端断开退出）；会话期间外部对 memory/ 的修改不会自动进索引（可 `memory_write` 自同步或重启）。serve 模式才有完整 watcher。符合「低资源下同时只跑一个实例」的决策。
6. **serve 关闭语义**：HTTP server 与 watcher 同进程；收到 Ctrl+C/SIGTERM 先取消 watcher、再 `http.Server.Shutdown`（5s 超时）优雅退出；HTTP 或 watcher 任一异常退出都会触发整体关闭。
7. **内存红线（< 60MB）**：serve 模式仍单进程（watcher+索引+MCP 合体，方案 A 的核心收益），无新增重依赖；Linux 上的 `/usr/bin/time -v` 实测留待阶段 5 统一做（本机为 Windows）。
8. **版本号**：v0.2.0 → v0.3.0（`cmd/zipper-agent-memoryd` 与 `pkg/mcp.Version` 同步）。
