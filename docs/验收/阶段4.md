## 4. 偏离与注意事项

1. **装配方式**（任务书允许二选一）：采用「独立接口由 serve 装配」——`AutoCommitter.Commit()` 由 serve 在 watcher 去抖批次 Handler 内同步调用（与索引更新同一 goroutine，天然串行，无并发 git 操作），`pkg/git` 不依赖 `pkg/watch`（与 design.md 的 watch 解耦原则一致）。
2. **`.git` 事件滤除（新增编排逻辑）**：git 自身写 `.git` 会触发 fsnotify 事件，若不滤除会形成「提交 → 事件 → 提交」反馈环。serve 层 `hasNonGitEvent` 滤掉纯 `.git` 内部批次；`pkg/git` 层另有「无暂存变更跳过」兜底（实测双保险生效，见验收 2 日志的 skip 行）。
3. **首次基线提交语义**：仓库缺失时 autocommit 自动 `git init` + 本地身份（不碰全局）；首个含变更的批次经 `git add -A` 把既有文件一并纳入首次提交。仓库已存在时本地身份缺失才补默认值（`zipper-agent-memory` / `zipper-agent-memory@localhost`），既有身份不覆盖（单测覆盖）。如需自定义身份：在 memory/ 内 `git config --local user.name/email` 即可。
4. **git gc 仅提示**：每次进程生命周期首次提交后日志提示一次「run 'git gc' periodically…」，从不自动执行（design.md R4）。
5. **Windows 实测说明**：`git bundle create` 的输出路径解析受 `git -C` 影响（相对路径落在仓库内而非调用方 CWD），migrate.sh 已修复（输出路径先转绝对）；bsdtar（Windows tar.exe）会把 `C:/...` 误解析为远程主机，验收脚本改用相对路径规避——均为脚本/测试环境问题，migrate.sh 本身在 Linux 上无此问题。zip 回退分支（未安装 zip 的本机未实测）为尽力而为路径，tar 为已验证主路径。
6. **配置文件方案**：任务书最终版（阶段 4）未包含配置文件交付项，采用纯 flag 方案（`-git-autocommit` 单开关，默认 false），与 design.md §8「默认关闭，由用户显式开启」一致；memory 路径/端口沿用既有 `-root`/`-addr` flag。若后续需要 TOML/JSON 配置文件统一承载开关/路径/端口，建议列入阶段 5 另立任务。
7. **stdio 模式无 watcher**：`stdio` 子命令不装配 autocommit（无事件流，会话期短）；autocommit 仅随 `serve` 常驻进程生效。符合「低资源下同时只跑一个实例」决策。
8. **版本号**：v0.3.0 → v0.4.0（`cmd/zipper-agent-memoryd` 与 `pkg/mcp.Version` 同步，阶段 3 同款约定）。
9. **未运行 `go test -race`**：本机 CGO_ENABLED=0（modernc 纯 Go 无 CGO 选型一致）；pkg/git 无共享可变状态（AutoCommitter 除 gcHintOnce 外为只读字段），并发正确性由 watcher 单 goroutine 串行调用保证，Linux CI 可补 race。
10. **真实 memory/ 零污染**：验收全程在 `$env:TEMP` 临时目录执行，结束后已清理；主仓库 `git status` 仅含交付物（`pkg/git/`、`scripts/` 新增，`cmd/zipper-agent-memoryd/main.go`、`pkg/mcp/server.go` 修改）。**未执行任何 git 提交**（协调者统一提交）。
